WHY THE TWO STEPS SHARE NOTHING - and it is policy, not oversight. Each preparation makes a root private to the run (native_lane_runner.rs:417-425, "No other run can name it"), and the workflow sets GUNBC_NATIVE_PRODUCT_REUSE=fresh on both steps (witnesses.yml:251 and :279). The code documents what that forgoes: a verified product-store hit "stands in for reconcile + emit + build + the red that admitted the entry", with the caller's door and refusal controls then running against the reused executable (native_lane_runner.rs:427-430). Under fresh, the store is neither consulted nor committed, and if GUNBC_NATIVE_CACHE_ROOT binds a store the run REFUSES (native_lane_runner.rs:434-443): "a restored final product may not stand in for the build this run owes". Under fresh no product key is even derived, because derive_key would re-ingest the corpus index and reload the closure just to hash it - the same work twice, DESIGN section 2, quoted at :451-454. So the 42m49s is cold by an explicit authorial ruling that the run owes the build.

CONSEQUENCES FOR THE 90-MINUTE PROBLEM, stated as decisions for you rather than as my proposal:
1. Cutting the emit cost means reversing that ruling - turning on the existing verified-hit path in CI - which changes what the gate proves. That is a semantics decision for the owners, not something I can justify from a performance goal, and it is exactly what DESIGN 2 forbids me from proposing as a cache that hides cost. I am recording it as available, not recommending it.
