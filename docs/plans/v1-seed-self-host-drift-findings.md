# Findings — v1 is not currently self-hosting (the `.dag` emits a non-building seed)

**Status:** execution-grounded findings note for the systemic §7 reconciliation effort (operator/bright-stag-routed, crisp-carp's `regen --verify` floor-gate depends on it). Captured by `cool-carp-699` 2026-06-23 while establishing the §7 fixpoint baseline for the Disposition-carrier slice-3 work. **DESIGN §7 is the authority; this is a transient handoff so the systemic effort inherits the execution, not a re-discovery — delete when the seed is reconciled.**

## The core finding (by execution, HEAD `c7962ab30f`)

**The current `.dag` source does NOT self-emit a building v1 compiler.** A full `regen_stage0` write (run in a throwaway worktree) produces a seed that **fails to compile — 764 errors**. The committed seed builds and works; it is a frozen, internally-consistent, **hand-maintained** snapshot that has diverged from the current `.dag`. Therefore `regen --verify` clean, `ci_fixed_point`, and `bootstrap_fixed_point` are all **systemically impossible right now** (the fresh crate cannot build), and any "bit-identical §7 fixpoint" receipt is unprovable against current main.

## Evidence

1. **Magnitude.** A full regen vs the committed seed: **84 files changed, 2853 insertions / 1690 deletions ignoring whitespace** (`git diff -w`). 62 of the 84 are core `std_*` / `v1_compiler_*` compiler modules — not peripheral.

2. **The seed does not build — 764 compile errors.** Representative (an emitted↔hand-maintained API contract that has drifted apart):
   - emitted code now produces `policy_serde_tag_field(...)` returning `String`, but the **hand-maintained** `wire_value_serialize.rs:168` calls `.unwrap_or_else(|| ...)` on it (expects `Option`):
     ```
     error[E0599]: no method named `unwrap_or_else` found for struct `String`
        --> wire_value_serialize.rs:168  policy_serde_tag_field(policy.clone()).unwrap_or_else(...)
        --> wire_value_serialize.rs:173  wire_variant_tag_for_policy(...).unwrap_or_else(...)
     ```
   The hand-maintained half and the freshly-emitted half have drifted into **type-incompatibility**.

3. **The "never regenerated" tell.** **All 89** committed `GENERATED_STAGE0_FILES` lack the `// Generated by v1 compiler -- do not edit.` header that the current emitter emits **uniformly** (the 4 genuinely-missing modules below all carry it when freshly emitted). The committed seed predates the header-emitting change and many emitter changes since.

4. **It is multi-point drift, not one regression.** The OLD emitter-gap signatures from prior sessions (`/* Type */` placeholders, dropped `wire_variant_tag_for_policy`) are **gone** — the emitter improved — but NEW drift (the `Option`/`String` mismatch above) keeps fresh unbuildable. Multiple independent drift points accumulated.

## Secondary findings (the regen tool is also bit-rotted)

These were found first; they are real but smaller than the core finding.

- **Two hand-maintained copy lists are stale** (omit modules added by #5566 / #5616), so `cargo fmt` aborts the fresh crate on dangling `pub mod` declarations — this alone kills `regen_stage0` (both modes) and `CI_PASS1`:
  - `src/v1/stage0/src/bin/regen_stage0.rs` `HAND_MAINTAINED_STAGE0_FILES` — missing `corpus_lex.rs`, `inert_carrier_project.rs`, `non_fold_residue_project.rs`.
  - `src/v1/tests/src/bootstrap.rs` `copy_stage0_support_modules` — missing those 3 **plus** 3 older ones (`cache_purity_oracle.rs`, `doc_reachability_project.rs`, `medium_structure_project.rs`). Authority for the full set is the emitter's `pub mod …` list in `src/v1/05_emit_rust.dag` (~line 1553).

- **Why it rotted silently:** `regen --verify` is not a CI gate (roadmap `5-regen-verify`, `done:false`). With no gate, PRs added modules / hand-edited the seed without re-seeding.
