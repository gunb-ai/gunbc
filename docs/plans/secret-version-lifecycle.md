# Secret version lifecycle: a subject-agnostic rotation kernel


---

*Provenance: this lane was carried as an Open Threads row in `DESIGN.md` until 2026-08-18, when that section was deleted on operator ruling — `DESIGN.md` is a first-principles document and per-lane status in it was a dual representation. The text below is preserved verbatim from that row; its authority is the carriers it names, not this file.*

**secret version lifecycle — a subject-agnostic rotation kernel (SECRET-VERSION-LIFECYCLE-0).** `gunbc.auth.secret_rotation` holds the version-rotation sequence once, parameterized by a `SecretRotationIntent`: observe → obtain replacement → **AddVersion exactly once** → read back the exact new version → verify the payload is the one written → verify the named consumers against that exact version → retire the prior → emit a `SecretRotationReceipt`. The kernel names no subject; its witness uses SYNTHETIC fixtures only. Wire decoding is **imported, never reimplemented** — `decode_sm_access_version_wire_response`, `decode_sm_resolved_version_identity_wire` and `SmResolvedVersionIdentity` with their typed refusals come from `extdeps.cloud.gcp.secret_manager` (landing jointly with #7995) — and **no arm binds a typed refusal to `_`**, because the incident this lane replaces was a production path that did exactly that and returned a fabricated `Secret` while every witness stayed green. The interface half adds `ListVersions`, `GetVersion`, `DisableVersion`, `EnableVersion` and `DestroyVersion` beside `AddVersion`; only disable and enable carry `idempotent`, because only they converge on re-issue — **AddVersion is not idempotent (every call mints a version, so a retry sprawls) and destroy is not (it erases bytes with no inverse)**. Walls, each with an executable forbidden arm: **exactly-once** — retry identity comes from a persisted attempt record plus the resolved identity, never from re-calling AddVersion; the issued-but-unconfirmed state is its own arm, resolved by *observing* the store, and refuses on a truncated inventory because a false *did not add* authorizes a second add. **Evidence must name a version** — success-only through the moving `latest` alias is refused. **Evidence selection classifies missing / unique / ambiguous** rather than taking the first match, since two disagreeing reports for one consumer is a contradiction and first-wins would render it a verdict. **Census completeness is an identity join** over a declared roster of branded `ConsumerId`, not a count. **A retirement is receipt-backed, never assertable**: `RetirementApplied` is reachable only through `DisableReceipt`/`DestroyReceipt`, each admitted only from an operation response whose observed state CONFIRMS the claim, so *we issued the call* cannot report as *it is done*. **Stated property of the kernel: no rotation artifact stores a payload digest, for any subject, at any strength** — a digest of a low-entropy or published string is credential material wearing a hash, and scoping the rule would require classifying entropy the workflow must not inspect, so the receipt keeps a payload-identity *verdict* and no arm can carry bytes. Branch cleanliness and credential revocation are separate standings; retirement-not-attempted is *known* still-live, not unknown. **Frontier, declared not stubbed:** nothing actuates — the operator-token route is refuted upstream (`ACCESS_TOKEN_TYPE_UNSUPPORTED`) and `gunbc.github_actions_wif` is absent from `origin/main` (measured 2026-08-13): the federation rows exist only on `origin/session/pi-reach-0`, whose PR #7971 closed 2026-08-07 without merge — dead work, not in flight. Revival onto a live branch versus fresh authoring remains an operator decision; actuation names (`github_actions_wif_pool`, `github_actions_wif_provider`, `github_actions_wif_provider_resource`, `github_actions_wif_attribute_condition`, `github_actions_wif_principal_set`) and deliberately does not copy them as a private duplicate until that single federation authority exists on main. **Explicitly out of scope, and blocked on observation:** rotating any *live fleet credential*. That is a separate lane (BMC-CREDENTIAL-ROTATE-0) which may not begin until a WIF-backed READ-ONLY probe establishes the target credential state, probing factory and managed access INDEPENDENTLY — both-accepted and neither-accepted are real states with different remedies, so a first-wins probe is a product collapsed into a coproduct. Until such a probe runs, the only honest standing for any BMC account is *unobserved*, and a committed fixture is authored data rather than an observation of it. Witness: `dag/test/claim/secret_rotation_witness_test.dag`.
