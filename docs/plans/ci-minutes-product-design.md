# GitHub-native CI minutes

**Goal:** customers install an App, choose an execution class/spend cap and change `runs-on`; existing workflow UI, logs, artifacts, checks, secrets and reruns remain GitHub's surface. Jobs are ephemeral and outbound-only, with no inbound service discovery, customer topology or persistent job state. This is an unimplemented design, subordinate to DESIGN's replacement-cut doctrine.

**Ownership:** generic fabric admission/allocation/budget/settlement cannot name GitHub protocol fields. A provider binding owns credentials, scale-set listening and acquisition. A reusable execution cell hosts the unmodified provider runner; adding another SCM adds a binding, not a fabric enum arm. `ExecutionClass` defines environment, CPU/memory, storage, isolation/network, duration and price; offers satisfy it. Physical host choice must not generate customer labels.

**Order:** observe exact external job → project demand → admit/reserve resources and money → construct cell/network and verify readiness → acquire the job → inject JIT/start runner → bind observed job/runner/cell → complete → verify teardown → settle. Acquisition is last among readiness commitments. Partition scale sets by customer scope, execution class, duration, isolation, network and pricing so arbitrary provider pairing cannot violate a grant. Preview API fields and pairing behavior require pinned, live verification before use.

**Cell contract:** one job per VM, disk, attachment, runner and JIT identity. Per-cell namespaces and explicit outbound destinations must leave no route to operator LAN/tailnet, BMC, host services or another cell. Compose the shared `std.access` kernel. Rate/byte limits and artifact/cache integrity remain obligations; network access is also an exfiltration/abuse channel. The short-lived scoped JIT secret must not persist on customer-visible storage. Teardown must independently establish attachment absence, disk removal and deregistration; any uncertainty retains reservations and withholds host capacity.

**Scheduling:** distinguish infeasible, not-yet-admissible, placement and fragmentation. Use exact member sets/NUMA domains, not aggregate free-core counts. Draining/backfill may admit only when provisioning bound + class maximum runtime + teardown bound fit the deadline; historical durations rank candidates but never authorize. Overruns require a typed kill with declared/elapsed values. At the initial small fleet, enumerate placements; measure starvation before building a speculative scheduler. Shared bandwidth/LLC contention survives VM isolation.

**Product decisions:** the operator must choose entitlement alone versus a measured variance bound, and any private-alpha interim boundary. Entitlement-first with variance measurement is the recommendation; arbitrary-code wall-clock guarantees and unmeasured variance promises are unsupported. Measure delivered quality/cost, not utilization alone. Platform diagnostics, lifecycle/resource/network/billing receipts belong here; customer logs remain GitHub's responsibility. Internal floor semantic-artifact work is a separate correctness lane.

**Replacement obligations:** retire shared-user/persistent-runner cells, global unprofiled reachability, vocabulary-only network accounting and offer-derived labels at their respective source roots. The old scalar `product.compute_fabric` root was deleted; do not rebuild it as the missing resource authority. The historical source readings are not a current fleet description.

**Validate:** exact-once demand identity; no acquisition after budget/offer/readback refusal; permitted public egress and structurally absent management/cross-cell routes; distinct concurrent cell identities; exact JobStarted binding; held reservations on uncertain teardown; refused reuse and management-reaching profiles; enforced runtime bound; supplier/SCM substitution without customer/core changes. No isolation, scale-set execution, queue-starvation or variance result is claimed by this note.
