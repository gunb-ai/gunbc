## 1. What this audits, and the one question it answers

The brief orders the census first. The question it must answer is not "how do we detect quadratics" but: **is a NEW structural-quadratic wall even on-dial, or is the decidable class already walled and the residue already correctly classified?** ROADMAP SS4 shelves the complexity-gate family explicitly ("a new wall must displace a measured cost on a pillar path to un-shelve"), so the census must locate every existing mechanism against the SS5 trichotomy and report what is already covered before proposing anything.

Method: inventory every mechanism that models, gates, budgets, or ratchets computational cost / algorithmic complexity / resource use; classify each as a WALL (fail-closed, bad state unwritable or errors), a RATCHET (a committed threshold that can be bumped), a RESIDUE LENS (a Bool check that concedes the bad state is writable), an AUDIT (emit-only, no gate), or INERT (machinery exists, nothing gates on it); record whether it is FLOOR-ENROLLED (a real consumer runs it green-by-execution); and mark whether it addresses STRUCTURAL/algorithmic complexity or merely RESOURCE budgeting.

## 4. The verdict -- the structural-quadratic class partitioned

Placing the census on the expressibility frontier's three regions for algorithmic complexity yields a clean, and somewhat surprising, result: **the decidable structural-quadratic WALL already exists.**

- **Region (1) -- Wall (already built).** Budget-dominance over the symbolic cost fold is decidable and IS walled: `cost.dag` `cost_lens` carries `WallNow`, folds `SymbolicCost` over the Node kernel, and detects Poly(2) structurally (Linear x Linear). `termination.dag` + the v1 `DescentEvidence` checker wall non-termination fail-closed. The memory actuator (`realization_width`) walls the resource symptom. So the OBVIOUS decidable quadratic *shape* -- a per-element loop whose body is itself linear in the whole input -- is already caught where the cost engine reaches.
- **Region (2) -- Lens-residue (the real gap).** The cost wall is **roster-bound** -- it does not walk the 1132-file corpus. Whole-corpus reach (ROADMAP SS3 `3-gates-whole`) is a SS5 residue that is *decidable but not yet unwritable*, and it is **blocked on the same reflection host-builtin** (`decl_facts(roots)` #5966, compile-graph gunbc#5364) that the emit-only audit bin is scaffolding around. The resolver-pathology quadratics live here too: measured, being killed by sibling lanes (bold-ibex-109 compositional `build_type_env`; representation-minimization), but with NO structural wall against *reintroduction* -- the floor memory cap bounds the symptom, not the shape.
- **Region (3) -- Review forever.** Optimality ("is this minimal cost?") is Rice-undecidable; synthesis ("produce a faster version") has no constructive patch. `synthesis.dag` is honestly `AdvisoryLens` / never-gates, and `complexity.dag` is honestly `RatchetForever`. Pricing either as a wall would be the SS5 "never" trap.

## 5. Recommendation (what the census determines about the wall)

1. **Do NOT build a new complexity oracle or cost-inference algebra.** The brief forbids both, and the census confirms the asymptotic engine already exists (`cost.dag`); a second one would be a SS3 fork of the cost authority.
2. **The only on-dial structural-quadratic wall increment is extending `cost.dag`'s reach whole-corpus** -- but that is region-(2) residue **blocked on `decl_facts(roots)` #5966 / gunbc#5364**, the identical blocker that shelves ROADMAP SS3 `3-gates-whole`. Until that host-builtin grounds, a whole-corpus asymptotic wall cannot be built without duplicating the emit-only syntactic proxy, which is exactly the scaffold to be dissolved, not extended.
3. **The measured-cost residue with the strongest pillar claim** is a *reintroduction wall* for the resolver-pathology quadratic shape once the sibling lanes land their fix -- a structural fence so the killed O(corpus^2) `build_type_env` shape cannot be re-authored. This is the single candidate that could "displace a measured cost on a pillar path" (ROADMAP SS4's un-shelve bar), and it should be sequenced AFTER bold-ibex-109 lands, co-designed with that lane, not raced ahead of it.
4. **Net:** DELIVERABLE 1 says the decidable class is already walled where reflection reaches; the wall lane's real content is not a new detector but (a) the blocked whole-corpus reach and (b) a post-fix reintroduction fence -- both gated on other lanes. Escalate the sequencing decision rather than improvising a redundant oracle.
