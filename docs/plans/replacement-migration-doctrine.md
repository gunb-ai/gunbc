# Replacement migration: cut over at the root

**Goal:** replace one semantic authority without retaining it inside its successor. **Method:** cut at the highest complete consumer boundary; delete the old route and fix forward from real obligations. **Validation:** one executing new authority, no old production consumers/adapters/fallbacks, every surviving obligation covered, and explicit retirement or restoration of silent residue.

Extracted from DESIGN §3 by operator ruling on 2026-08-18. This file owns the procedure and exceptions; DESIGN owns the principle. The [pinned prior text](https://github.com/gunb-ai/gunbc/blob/06d3c1c3149a7420c4a548b9aba9b15c721c635d/docs/plans/replacement-migration-doctrine.md) retains the full dated receipts and original explanations. The following preserves their operative conditions.

## Default and exceptions

A replacement occurs when two structures answer the same semantic question and one must disappear. Do not refine old authority X layer by layer into Y: that makes adapters, fallback and intermediate representations production obligations. Delete superseded production routes, machinery, flags and dispatch as early as possible; X’s continued availability invites investment and new decisions in its obsolete model.

The default is delete-first with minimal Y able to hold the boundary immediately, even while under-covering, under a declared bounded rung drop: previous rung, temporary rung, reason and restoration trigger. Two exceptions:

- **Gap-intolerant boundary:** outward-facing interfaces, irreversible effects or safety floors others depend on require Y in shadow, then one accepted root switch that deletes X in the same motion.
- **No viable Y:** X may remain only **frozen**, including registries, host builtins, escape arms and compatibility tables. No feature completion, new rows or investment; use it as quarry until a candidate can hold the boundary.

Existing plans supply evidence about terminal shapes and obligations, never authority to defer the cut through their old sequencing. Enumerate what is certainly scheduled for deletion and remove it before fix-forward work. Current, specifically superseding operator rulings still govern their stated scope.

## Establish a discriminating red

Deletion discovers loads and defects X concealed only where the actual acceptance path refuses broken dependencies. **Before interpreting destruction-green, destroy one genuinely required edge and exhibit RED on the same command, mode and reachable arm.** Discharge this per axis: a name-resolution red proves nothing about type binding. Without a reachable red, the missing wall is the finding; more green samples do not establish coverage.

This destruction-witness rule is currently review discipline, rung1/mitigatable. A structural executor binding witness axis/path and rejecting fail-open acceptance arms does not yet exist; citing this document is not coverage.

Name the populations deletion cannot make loud: un-enrolled evidence, external consumers, already-silent coverage and prose-named referents. Their restoration/retirement is part of the bounded gap. Prose naming a deleted workflow is not a dependency edge and can continue asserting false present-tense behavior. Until carriers reference the typed artifact identity, **grep for the deleted names in the same change** and rewrite the references found; an empty search is not proof that no reference exists, and no completeness is claimed. `generated_artifact` variants and workflow symbols provide existing homes; closed-coproduct consumers make retirement visible where adopted. A recurring prose sweep is mitigation, not the class fix.

Historical evidence: #8283 deleted workflow files while prose survived; #8774 repaired dangling symbol citations but could not cover filenames in prose. The live `gunbc_ci_collect_fleet_convergence_invoke` claim had no surviving workflow consumer. `proxy_observation_mistaken_for_action_semantics` records the import-strip case where existing edges still produced green because the reachable checker declined to judge them. Raw dated counts remain in the pinned receipt; heuristic English classifications are hypotheses, never defect measurements.

## Root-first procedure

1. **Name exact root and subject:** consumer × subject population × semantic contract. “Parser”, “CI” or “v1” alone is insufficient. Find production consumers by named grep and source inspection before assigning descendant migration work; report the dependencies found, claim no completeness, and do not hold the cut for a global inventory.
2. **Trace one complete semantic vertical** backward from that consumer. Determine the smallest Y that answers its actual question, including every required refusal; do not translate X’s internal layers by default.
3. **Delete production X** under the applicable default/exception above. Keep history/pinned X as evidence or external oracle, not live fallback.
4. **Fix forward by deliberately chosen class:** implement terminal capability in Y; migrate source using independent offline X evidence; retire an obsolete need with receipt; or, if the error reveals another obsolete authority, recurse to its root. Distinguish dependency loads from previously concealed defects. Apply each chosen class mechanically; do not bulk-restore old bindings to obtain green.
5. **Close against Y’s green**, not X’s output shape: enrolled gates/tests pass through Y and all declared silent residue is restored or retired. Staged admission joins exact dispositioned identities and deletes X’s route in the same PR completing that join.
6. **Retain evidence for surviving claims.** Re-enroll discriminating controls against Y. Delete X-only implementation/comparison machinery. Retire with receipt a witness whose sole subject is intentionally rejected behavior; do not let that test force obsolete behavior back. A climb preserves its claim/control; deliberate rejection retires the claim itself.

From the first increment, Y has one executing root, exact subject, typed outcome and discriminating red. Every admitted component’s semantic authority and consumer must survive terminal Y substantially unchanged; its internals may refine.

## Supersession and disposition

A root is consumer-relative, not a file. If replacement `b1` covers the complete admissions/refusals of `b→c→d` and dominates every production path into those descendants, delete `c`/`d`; no `c1`/`d1` representation is owed. Any outside consumer makes its dependency an independent root to analyze. Evidence of a surviving requirement transfers to the new root even when its old representation disappears.

Every retained artifact must have a terminal consumer. Otherwise it belongs in branch-local experiments, historical quarry or the deletion population. A current caller establishes migration cost, **not correctness or a duty to survive**. Disposition obligations as unchanged retention, changed terminal contract, replacement by named Y, evidence-only for a surviving claim, or retirement with reason. Retention needs a surviving external contract, invariant, stored-artifact compatibility, independently useful consumer, deliberate transition or rollback commitment.

Admission requires both `undispositioned consumers = 0` and `uncovered surviving consumers = 0`. Undecided blocks but is never presumed retained; retired obligations need no coverage. Internal delete-first obtains dispositions through breakage/fix-forward. Where deletion cannot be the instrument (gap-intolerant/frozen boundaries and silent residue), the author names the consumers found by scoped inspection and states what remains unknown. A disposition or consumer census is not a prerequisite: it is retired by the 2026-10-30 process ruling (`gunbc.design_ruling bad_process_is_worse_than_no_process`). This does not establish corpus-wide coverage; changes use scoped review and focused tests, and the actual correctness requirements (every required refusal preserved, no surviving production consumer of X in the change's reach) remain.

`gunbc.replacement_cut` owns `ReplacementCut`, `ConsumerDisposition` and `admit_replacement_cut_plan`:

- `HigherBoundaryAnswer` must explain why not higher; descent names its parent by joinable `ReplacementCutId`.
- `BoundaryCensus` distinguishes genuinely consumer-free with basis from enumerated-but-empty, which refuses.
- Closed `ExternalXRole` permits bootstrap producer, independent differential oracle, mechanical source migration or historical measurement; forbidden fallback/internal resolver/production second opinion has no constructor. No-oracle-needed needs a reason; an enumerated empty role list refuses.
- `EvidenceDisposition` re-enrolls, replaces, retires with reason or explicitly parks undecided; undecided evidence blocks like undecided consumers.
- Admission reports all typed causes: undecided rows; uncovered surviving consumers; coverage/replacement naming X itself; duplicate consumer/evidence/region member; identical old/new roots; self-referential descent; empty external-role enumeration or covered region.
- `AdmittedReplacementCutPlan` is sole-constructor/caller-sealed to the admission fold, carrying cut identity and digest over every plan field; `admitted_matches_plan` recomputes. Authoring an admitted flag cannot qualify another plan.

That plan admission does **not** establish an independently observed consumer census, obligation-grain coverage or executed parent-refusal receipts, and it owes none of them: the census prerequisite is retired by the 2026-10-30 process ruling (`gunbc.design_ruling bad_process_is_worse_than_no_process`). The executed parent-refusal and obligation-coverage requirements stay with the change's focused tests. No roadmap node is structurally registered to a cut merely because this plan exists.

## Independence, vehicle and descent

Y may reuse stable primitives: tokenization/parsing, Node/Edge, occurrence identity, source inventory and target-independent evaluation. Independence means X cannot determine Y’s production answer. No internal resolver, implicit provider, fallback, controlling second opinion or X implementation behind a Y-shaped carrier. Oracle agreement compares independent answers over the same subject.

“Atomic” is the authority transition, not a requirement for one commit, one development PR or repository-wide migration. A breaking delete-first cut uses an integration branch from a recorded main base, root deletion first, fix-forward there; main receives one green cutover merge. Region work targets that branch and inherits X’s freeze; no broken mid-loop main or dual-authority production interval. Staged Y runs a real shadow consumer before its accepted switch.

If a cut is too large, partition complete consumer cohorts, **not internal layers**. A completed cohort runs exact subjects through Y, is physically absent from X dispatch/scheduling and has no fallback.

Try the maximal root cut first; descend only after exact refusal:

- **Y incomplete:** implement the missing terminal behavior and retry the same boundary.
- **Escaping consumer:** redirect to Y, enlarge the region or explicitly retire it.
- **Opaque refusal:** bisect to locate the obligation; bisection diagnoses, it does not prescribe migration order.

A lower boundary is legitimate only as fallback from a refused root cut, when it is independently meaningful in terminal Y, covers every crossing obligation without an X-only adapter, immediately deletes a nonempty X region and survives terminal Y. Search the semantic cut by proposing maximal regions, splitting only refused portions and pruning covered ones. The envelope extends both downward through implementation and upward through X-only adapters/repair/workarounds until an independently justified contract stops it.

Selective loading, affected sets, caches, batching, aliases and short names follow correct Y semantics. Begin with the simplest complete subject/canonical naming/manifest/fold, then derive optimizations. New production adapters, migration flags, dual dispatch or fallbacks are active debt requiring external operator approval of the exact introduced population. Disposable branch-local experiments must be deleted before merge.

## Terminal receipt

Name exact old root/subjects, new root, independent outer oracle, cutover consumer, deleted production machinery and retained evidence. Observe:

```
new root consumers               = exact declared population
old root consumers               = 0
undispositioned consumers        = 0
uncovered surviving consumers    = 0
production X↔Y adapters          = 0
production fallbacks             = 0
migration feature flags          = 0
unreconciled subject identities  = 0
retained discriminating evidence = exact declared population
retired consumers and evidence  = exact declared population, each receipted
```

Ordinary refinement remains valid when one authority survives terminal architecture and no consumer needs both representations. Judge authority reduction, not diff size.
