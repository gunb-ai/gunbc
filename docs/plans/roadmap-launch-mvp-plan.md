# Roadmap launch MVP

**Goal:** edit the roadmap, deploy the exact admitted revision, launch one ready canary, observe one worker complete its bounded change, verify/publish that exact head, explicitly accept it and see its dependent child become structurally Ready. Tests, deploy alone or manual branches/host edits do not satisfy this production terminal.

**Method:** one shared launch decision feeds UI, manual POST and timer. It proves actuatable instance, clear transition, exact desired/deployed revision agreement, eligible node with complete execution contract/size, closed dependencies, no live owner, available capacity and permitted cause. Production `ManualReady` permits operator launches of Ready work while the timer only reconciles/verifies/publishes/cleans. Ordinary node-ID override disappears; any future break-glass path needs separate typed authority and is outside this project.

| Gate | Required receipt and discrimination |
|---|---|
| RLM-0 | Freeze parent/child IDs, exact allowed sentinel/nonce mutation, direct pinned oracle and criteria/authority digests. Keep production canary inert. Red on missing/wrong dependency, identity, nonce or unspecified launch contract. |
| RLM-1 | All three surfaces project the same launch identity/reason. Refuse blocked child before effects, timer spawning in ManualReady, drift and duplicate attempt creation. |
| RLM-2 | Existing reviewed fleet plan/apply/deploy joins exact main/desired/deployed revision, plan fingerprint/baseline/lease, tree digests, readiness/transition, services/mode, mutable-root footprint, provider preflight and observable attempt ledger. Wrong revision, changed tree, retained transition marker, unwritable roots, missing provider or unread observation refuse. |
| RLM-3 | Deploy the exact live two-node authority only after predecessors. Page and workflow JSON agree: parent Ready, child blocked by that parent, no ordinary child launch, no timer-created attempt. Unread ledger is not idle. |
| RLM-4 | One browser action joins admitted identity, attempt/base/provider, one branch/worktree/process and durable record. Second click returns existing attempt; child refusal precedes filesystem/provider effects. Lost persistence is failure even if a process runs. |
| RLM-5 | Exact attempt completion, bounded diff and detached exact-head pinned validation precede confined publication. Join node/attempt/base/head/criteria/oracle identity and outcome. Wrong nonce/path/oracle/request identity or publication failure cannot synthesize success. |
| RLM-6 | Merge plus explicit acceptance of the exact result advances the parent to Done and child to structural Ready; merge/self-report alone cannot. Wrong/lost acceptance leaves child blocked, and accepted parent relaunch refuses. |

**Amendment:** only the parent is the execution canary. The child needs structural `SchedulingReady`, not a complete execution contract or admitted Launch. The original “launchable child” wording was superseded by the manager's 2026-08-29 ruling; unspecified work must still refuse launch.

**Frozen chain:** criteria/authority → admission/deployment → served revision/tree → attempt/base/provider → exact head/verification/publication → accepted identity/child projection. Bind immutable predecessor receipts, never latest. A single manager opens serial gates after reading the actual producer; downstream work may prepare inert schema/fixtures/falsifiers but cannot activate production or mint success early. Reports name producer/source/instrument/host and identities. Refusal is evidence, not permission to bypass a gate. Generated/host changes use their existing producers.

**Recorded deployment blockers:** the 2026-09-02 plan/apply generation advance remains valid evidence and must not be replayed merely because its revision aged. The independent `LegacyGitFileSyncNotAdmitted` wall prevented the deployment terminal until a real Git-native transition exists. Complete transaction-input projection is another unmodeled obligation: semantic/code/payload/history inputs and every phase must share a typed projection receipt before exact-revision equality can narrow. Same tree or path digest alone does not preserve ancestry/forward-only guarantees. The historical stall was not enrolled in `all_guarantee_stalls`; its absence cannot be read as closure. Recheck these owners before another close attempt.

**Validation:** execute the whole browser→attempt→verification→publication→acceptance chain on production with the table's adverse controls and independently read release/tree/standing. Current DESIGN governs CI; prior baseline green is not today's receipt. Fabric own-CI, automatic scheduling, provider arbitration, ctrl revival and blue/green are excluded. After the terminal, automate desired-ref convergence, online/offline catch-up and complete host/phase reporting through the same actuator; make dashboard deployment a normal member without changing this acceptance contract.
