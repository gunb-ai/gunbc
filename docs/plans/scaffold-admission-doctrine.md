# Scaffold admission doctrine: a dissolution condition is not permission

*Provenance: these three operator rulings were carried inline in `DESIGN.md` §5 until 2026-08-18, when they were extracted on operator ruling — `DESIGN.md` is a first-principles document and these are admission policy. Text preserved verbatim. §5 states the principle and links here; this file is the authority for the verdict vocabulary, the approval-is-external rule, and the out-of-band actuation carve-out.*

**A dissolution condition describes how admitted debt ends. It does not authorize creating the debt** (operator ruling, 2026-08-10). This supersedes, rather than supplements, the clause that formerly closed the paragraph above — *the only two landing states are the real fix, or a declared scaffold* — because in practice the trigger became a permit: *I know this is temporary, but I registered its future deletion, therefore it may merge.* **The default and expected landing state is the final construction. A scaffold is not an ordinary alternative to it; it is an operator-approved exception.** Any pull request whose current head introduces a net-new active dissolution obligation without an explicit operator verdict on that exact population is a **hard reject**: marked-but-unapproved debt is refused, and unmarked debt is the same violation plus concealment. The normal response to a proposed dissolution obligation is to back up and finish the underlying modeling, decomposition or generation work before using it; approval exists for exceptional cases, not as a routine route around that work. The rule follows from §2 rather than being layered onto it — redundant work spends someone else's future time for the author's present convenience, *including by building something destined to be thrown out* — so a throwaway artifact's cost is authoring plus review plus maintenance plus deletion plus review of the deletion, against a benefit bounded by its lifetime, and if the modeled path already exists the benefit is zero and the trigger was ceremony.

**Lifecycle and admission are two questions, and the repository was conflating them.** *How would this temporary thing disappear?* is the generic lifecycle authority's: a bound condition carries a checkable trigger, an unbound one is honest prose structurally unable to report itself fired. *May we introduce this temporary thing at all?* is separate and project-level, because neither arm says the construction was justified — wrapping prose in an unbound condition beats letting prose impersonate a checkable trigger, and makes the underlying work no more sustainable. Likewise `std.disposition` `Scaffold` carries a construction mechanism and a declaration binding, and nothing else: no operator authorization, no proof the final path could not be built now, no benefit bought, no assessment of whether an already-modeled path was available. So the verdict is **not a Boolean**: *RejectAndFinishNow* (back up and build the sustainable path in this PR — the default), *ApproveTemporaryIntroduction* (this exact temporary construction may land), *AcknowledgePreexistingDebt* (the PR discovered and modeled debt already present on the base; it did not create it). Only the second admits **new** debt; the third exists so that documenting previously hidden debt never reads as creating it, which is the incentive that would otherwise keep it hidden. **Approval is external to the diff:** a row the PR authors itself is not approval — the author could write an approved flag as easily as the scaffold — so it is an *observed* fact (the configured operator, an APPROVED review, bound to the current head, invalidated by any later push, presented with the exact derived new-obligation set). And one obligation covers one independently removable unit: several artifacts share one only when they have the same terminal construction, fire on the same observation, and cannot survive one another — otherwise a single broad trigger launders an expanding collection of temporary work.

**Out-of-band actuation has no ordinary scaffold arm** (same ruling; receipt gunbc#8073). Where the final path is *modeled intent → generated plan → modeled host-effect actuation* and the temporary path is *hand-authored YAML → embedded shell → host mutation*, the temporary artifact is not an early version of the final one — it never becomes it by refinement; it is deleted whole while the real path is separately authored. A hand-authored workflow, deploy script, migration script or manual mutation path that stands beside, bypasses, or will later be replaced by a modeled actuator is **manual application committed as source**: hand-writing an actuator is hand-applying it with a commit wrapped around it. Branch-local experimentation stays fully open — the canary may run, produce measurements, and be **deleted before merge**, leaving the modeled facts the final route consumes. Experimental work is not valueless because its implementation is disposable; it becomes waste when the disposable implementation merges into the long-lived authority and thereby imposes review, maintenance, interpretation and deletion work on everyone else. The mainline choices are the modeled path or nothing, except under an explicit operator ruling bound to the current head. Receipt: gunbc#8073 added three hand-authored Spark workflows beside the modeled convergence spine (`gunbc.fleet_converge_timer` → `gunbc.fleet_converge_apply` → `gunbc.host_effect_realize` `host_effect_apply`), one of them registering a `Scaffold` whose own note said the construction was *exactly the class the shell → intent routing forbids* — the trigger standing in for the decision. All three were deleted; the disposition had no subject once they were gone.
