# srv1 workspace VM bringup

**Goal:** prove one operator-owned workspace lifecycle on srv1-13 through existing commissioning, allocation and cleanup. Customer creation, extra hosts, CI migration and automatic expiry scheduling are outside this scope.

**Recorded boundary, 2026-10-09:** image/controller, network receipt and slot limits passed independent readback. Initial sanitation could not observe attached TUN queues on the running kernel. A canonical dependency proposal and a first non-interrupting runner drain were observed; installation, reboot, commissioning, VM boot and authenticated guest SSH remained unproven. These are dated receipts, not current host status. Workflow green and `FullyApplied` commands alone did not prove the lifecycle.

**Method:** build the image through `workspace_image_build`; its filesystem is not reproducible, so bind measured bytes through `workspace_artifact_policy`. Install the exact reviewed controller release and image with independent executor/policy/image custody checks. The artifact run ID locates bytes, never authorizes them. Converge the selected cell boundary, authenticated state service and network through existing plan/apply; initialize its root-owned receipt from live reads without overwriting another generation. Preserve historical refusals and the slot's workspace ownership.

Use installed operator policy and the dedicated srv1 guest key, with host-local access distinct from gateway evidence. `workspace_operator_request_wet` admits a canonical policy-bounded expiry; jobs neither receive the state MAC key nor create/release requests. Allocation apply consumes the reviewed exact request/generation, never “latest.” Observe via `workspace_operator_observe_wet`; authenticate the guest host key and execute an identified guest command. Release via `workspace_operator_release_wet` using reservation generation, reconcile, then prove same-slot/new-incarnation reuse and explicit expiry cleanup. A recorded request or SSH client configuration is not a guest-login receipt.

**Kernel dependency:** `gunbc.host.host_kernel_dependency` selects the provider after the actual TUN query. Only numeric unsupported-operation evidence demands a provider; permission/device/parse/reader errors and multi-queue mismatch refuse. Backported success needs no upgrade, and a nonzero queue count still fails sanitation. Bind exact host/source/interface/boot identity, packages and non-removing simulation. Installed matching artifacts need activation only; an already-running selected kernel that still refuses must not reboot-loop.

**Maintenance:** `host_kernel_dependency_apply` consumes that canonical proposal through root-only drain/install/activate/verify entries, outside job-user grants. Runtime masks let existing jobs finish; all runner instances, descendants and queued work must be observed drained before installation/activation. Unknown/foreign census, live controller, boot/proposal drift or unread state refuses; preserve permanent masks. Verify exact installed boot artifacts, GRUB target and absence of override before an explicitly authorized OS reboot. On return require new boot identity, target release, actual queue capability and service recovery, then repeat full commissioning. Abandoned pre-reboot maintenance removes only that attempt's runtime masks. Console recovery must be established; retaining old kernels is not automatic rollback. No historical approval here authorizes a new interruption.

**Validation:** retain a joined live chain for image/controller readback, commissioned slot, ready allocation, authenticated SSH, release, reuse, expiry cleanup and final released/ready state. Separate desired command success from effective resource limits; use independent digests when transport trims bytes. Reader/publisher network populations must share the deployment authority; workload admission remains separate. Keep the exact policy read grant and protected-state custody. Scoped model/manual checks and historical CI are not current live proof. The original account retains run IDs, hashes, canonical dependency logs and `target/srv1-bringup-evidence/` locations; never publish private keys or signed envelopes.
