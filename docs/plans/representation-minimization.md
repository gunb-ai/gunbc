## Lever C (item 2) disposition — design note (2026-06-28)

Design-first investigation result. The §2 finding is real and verified by execution: the floor / claim-execution interpreter consumes only the resolved Node tree (module items + item_registry + source_indices), NEVER the per-module type_env/func_env (proven by a discriminating teeth control — evicting items/item_registry turns reflection witnesses RED, while evicting only type_env/func_env keeps the whole 1109-witness floor GREEN). The emit path (a separate process) genuinely consumes the envs and stays byte-identical.

Extend, do not fork (DESIGN §3): the v2 self-host compiler ALREADY models the consumed-core-vs-envs split — `03_resolve.dag` `ResolvedTree = Node` (env-free) versus `04_infer.dag` `InferredTree { root: Node, facts: Map<Node, InferredFacts> }`, where the facts side-map (grounding + termination descent) is v2's analog of v1's type_env/func_env. v1's monolithic `ResolvedGraph { Vec<TypedModule { type_env, func_env }> }` is the bootstrap-seed artifact that conflates what v2 already splits. No new resolve-output type is minted; Lever C aligns to the existing v2 types.

The v2-surviving root is a RETENTION/EVICTION POLICY, not a type and not a fact-elimination: a module's inference facts are live only while it and its DIRECT dependents are processed (typecheck reads direct imports' facts; imported types are copied by value), so a module's facts evict once the dependency frontier passes — peak bounded by frontier width, not total modules (the #5867 shared-intern_table precedent: an algorithmic single authority). v2 `00_compile` today holds `InferredTree` WHOLE across infer→lens-gates→emit/eval, so this bound is genuinely OWED at v2 `00_compile`, unrealized.

Why this is a design note and not a modeled lens today (DESIGN §5/§6): v1 is hand-written bootstrap Rust that does NOT consume the .dag authority, so a .dag-modeled bound plus a hand-coded v1 frontier-evict would be parallel representation with no derivation link, and a lens asserting the bound over v2 infer would be inert (v2 infer is not the live path — no executing consumer). The bound is therefore recorded here, to be realized as v2 infer's streaming-infer when v2 becomes the live compiler. The interim bulk-eviction PR (#5886) was dropped: it trimmed only SUSTAINED interp RSS, not the per-shard resolve/infer PEAK that is the floor OOM axis (concurrency is peak-bound, #5867/CI-floor).

Open decision (data-gated), A3-DEFAULT with an explicit flip trigger: by default frontier-evict stays a design note (A3) and is NOT cemented into the doomed v1 typecheck seed. FLIP TO A1 (implement v1 frontier-evict) IFF the measured residual per-shard peak EXCEEDS the container cap AFTER the cheaper fixes are in — the floor alloc-clamp (concurrency bounded to the live cgroup limit, already landed) plus Rc-shared signatures (the remaining precondition, gated on the variant-owner-by-expected-type grounding keystone via its empty fixed-seed emit-diff). If a residual-over-cap survives those, frontier-evict is the necessary doomed-seed residual, justified by live acute pain exactly as the shared-intern_table fix was; otherwise A3 holds and frontier-evict waits until v2 infer is the live path. The doomed-seed Rust is written only if/when the data trips that trigger — this note costs nothing. Measurement method: per-shard peak via the claim_executor path, reporting RUSAGE_CHILDREN floor-aggregate AND single-process VmHWM as distinctly-labeled numbers, compared against the cap.
