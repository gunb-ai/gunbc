# Resolved-graph representation minimization (root-first, v1-survivable)

Status: operator-funded 2026-06-27. Steer: minimal representation, attack root causes as much as we can, v1 is going away. This is the resolved-graph REPRESENTATION-minimization follow-on to the acute floor-OOM fix (#5867 shared InternTable: whole-tree resolve 14.2 GiB to 5.5 GiB, 61 percent reclaimed). It repoints the orphaned tidy-wren-707 resolved-graph-minimization lane. Distinct from `docs/plans/resource-aware-scheduler.md`, which is the ALLOCATION lane; this lane is REPRESENTATION minimization at the root.

## The discriminator: root authority vs doomed seed

v1 is going away, so every item is gated on one test: does the fix live in the `.dag` authority (and therefore survive into the v2 self-host), or is it a hand-edit to the doomed v1 Rust seed (and therefore die with v1)? Root items live in this plan. v1-only polish is explicitly de-scoped to bank-if-cheap and is NOT a pillar.

## Current footprint

Whole-tree resolve is about 5.5 GiB for about 7.5 MB of source: roughly 730x source-to-resolved. That is the width-1 all-modules-live worst case; the sharded CI floor holds only a subset per shard and sits under cap post-#5867. The footprint is now LINEAR with no quadratic OOM. Target: 20 to 50x. The path is structural (the levers below), not another big dedup: the func_env.sigs second-quadratic is real but only hundreds-of-MiB because its heavy provenance payloads are already Rc-shared (established by code read of `declared_to_resolved` and `merge_scope_from_imports`, not a probe).

## Lever C (item 2) disposition — design note (2026-06-28)

Design-first investigation result. The §2 finding is real and verified by execution: the floor / claim-execution interpreter consumes only the resolved Node tree (module items + item_registry + source_indices), NEVER the per-module type_env/func_env (proven by a discriminating teeth control — evicting items/item_registry turns reflection witnesses RED, while evicting only type_env/func_env keeps the whole 1109-witness floor GREEN). The emit path (a separate process) genuinely consumes the envs and stays byte-identical.

Extend, do not fork (DESIGN §3): the v2 self-host compiler ALREADY models the consumed-core-vs-envs split — `03_resolve.dag` `ResolvedTree = Node` (env-free) versus `04_infer.dag` `InferredTree { root: Node, facts: Map<Node, InferredFacts> }`, where the facts side-map (grounding + termination descent) is v2's analog of v1's type_env/func_env. v1's monolithic `ResolvedGraph { Vec<TypedModule { type_env, func_env }> }` is the bootstrap-seed artifact that conflates what v2 already splits. No new resolve-output type is minted; Lever C aligns to the existing v2 types.

The v2-surviving root is a RETENTION/EVICTION POLICY, not a type and not a fact-elimination: a module's inference facts are live only while it and its DIRECT dependents are processed (typecheck reads direct imports' facts; imported types are copied by value), so a module's facts evict once the dependency frontier passes — peak bounded by frontier width, not total modules (the #5867 shared-intern_table precedent: an algorithmic single authority). v2 `00_compile` today holds `InferredTree` WHOLE across infer→lens-gates→emit/eval, so this bound is genuinely OWED at v2 `00_compile`, unrealized.

Why this is a design note and not a modeled lens today (DESIGN §5/§6): v1 is hand-written bootstrap Rust that does NOT consume the .dag authority, so a .dag-modeled bound plus a hand-coded v1 frontier-evict would be parallel representation with no derivation link, and a lens asserting the bound over v2 infer would be inert (v2 infer is not the live path — no executing consumer). The bound is therefore recorded here, to be realized as v2 infer's streaming-infer when v2 becomes the live compiler. The interim bulk-eviction PR (#5886) was dropped: it trimmed only SUSTAINED interp RSS, not the per-shard resolve/infer PEAK that is the floor OOM axis (concurrency is peak-bound, #5867/CI-floor).

Decision (MEASURED 2026-06-28): A3 — frontier-evict is NOT written into the doomed v1 typecheck seed; the ~4 GiB eviction prize is captured durably by the v2 streaming-infer realization of the frontier-bounded retention bound (the resolution-strategy fact above), when v2 infer becomes the live path. This was a data-gated decision and the data resolved to A3, robustly: the post-cutover floor measurement (claim_executor per-shard VmHWM × spawn_width=2, sccache excluded as a separate process tree) is co-resident 5.98 GiB — 1.82 GiB UNDER the ~7.8 GiB safety threshold below the 8 GiB host cgroup cap, only +0.7 percent above the 5.94 GiB pre-cutover baseline (noise). The cheaper fixes already in main — the floor alloc-clamp binding concurrency to the live cgroup limit, the shared intern_table, and the spawn-width-from-budget throttle — hold the floor comfortably under cap, and the cutover does not regress it. So v1 frontier-evict is NOT forced (the acute-pain justification that would have cemented doomed-seed Rust is absent). Its residual value at this margin is throughput-headroom (a lower per-shard peak permits a higher spawn_width), which belongs to the allocation lane (`docs/plans/resource-aware-scheduler.md`), not this representation lane. Verdict metric note: co-resident = per-shard VmHWM × spawn_width is a deliberately conservative upper bound (assumes simultaneous shard peaks), the correct fail-closed bias for a hard cap; the 1.82 GiB margin makes A3 robust rather than borderline. The flip-to-A1 trigger stays documented and re-auditable: if the corpus later grows enough that the post-cutover co-resident peak reaches ~7.8 GiB, A1 re-activates — implement frontier-evict on the claim-scoped `MultiEntryIndex.typed_module_cache` (eviction predicate fail-closed: a module's typed graph is evictable only once every module that imports it has been resolved, conservative-when-uncertain), gated on a consumer-completeness design read since that cache is load-bearing floor infrastructure. UN-tripped today at the measured 1.82 GiB margin.

## Lever B (item 3) — arena/index deepening (2026-06-28)

Base measured at commit 529fd65044 (post-#5910). Floor self-RSS at width=1 = 5.12 GiB; cgroup peak 5.31 GiB; serial per-shard peak ~4.82 GiB = ~94% of the floor. Source text: 7.58 MB / 1409 files / 221k lines = ~400x blowup to resolved graph.

### Node anatomy (verified)

`Node` at `src/v1/stage0/src/v1_std_core.rs:742`. `size_of::<Node>()` = 144 B; the 18-field superset struct the sequencing item describes. Rc-wrapped = 16 B Rc ctrl + 144 B = 160 B minimum per node before String/Vec allocations. 12 pointer fields (96 B): `span`, `ident_span`, `children`, `params`, `uses`, `properties`, `body`, `transport`, `type_annotation`, `inferred`, `match_pattern`, `expr_data`. Plus 24 B inline `String name` and 16 B `Option<i64> ident`. `SourceSpan` at `std_types.rs:265` = 40 B: `file: String(24)`, `start: i64(8)`, `end: i64(8)`. The '76 percent unused per leaf' and '144 B / 12 pointer fields' views are the same struct — per-kind sum type (sub-move i) eliminates unused fields per kind; arena/index (sub-move ii) replaces the Rc boxing around it.

### Sub-move ii: arena/u32-index container

Decisive structural fact: the Node graph is an ACYCLIC downward-only DAG — no parent back-pointers, no cycles (DESIGN §4 guarantees). `Rc` exists for shared ownership plus cycle safety; the Node graph uses neither of those properties, only downward sharing. So 16 B/node refcount plus per-node malloc header pays for an unused capability.

Proposed replacement: a `u32` index into one `Vec<Node>` arena (4 B, no ctrl block, no per-node malloc header). Four child-Vecs become `(u32 start, u32 len)` slices into a shared edge-arena. This erases the 16 B ctrl/node plus per-node allocator overhead, and halves all 12 pointer fields (8 B ptr to 4 B index). Structural sharing is preserved for free: two u32 values pointing to the same slot share the subgraph without reference counting. Estimated node-graph memory cut: ~40 to 55%. Composes with struct-of-arrays layout (columnar, recovers alignment padding ~10 to 15%) and spans-as-side-table (file path stored once per file, span encoded as 2 x u32 = saves ~20 B/span vs per-span String).

### Cheap recoverables (gating varies per item — see plan discriminator)

Smaller wins. Per the plan's root-authority discriminator: fixes that live in the `.dag` authority are root items; fixes that hand-edit the v1 seed are bank-if-cheap and die with v1. The gating varies per item below — none of these is unconditionally independent of the emitter gate:

- Empty-Vec singleton — already recorded as landed (~43.7 MiB, #5878). Verify all call sites use the singleton; if any still inline `Rc::new(vec![])` on the seed path, that is bank-if-cheap v1-seed work (dies with v1, not a root item).
- `Option<i64> ident` to u32 with 0-sentinel — saves ~12 B/node. As a Node representation change, the `.dag`-authority path is gated on #5879 (same as Lever B); the v1-seed path is bank-if-cheap. `Node.ident` is a live ident-keyed fast-path on module/import nodes — u32-shrink is fine; deletion is refuted by execution.
- `SourceSpan.file: String` to a u32 file-id side table — saves ~20 B/span. Same gating note as ident: the `.dag`-authority path is gated on #5879; the v1-seed path is bank-if-cheap.
- Kernel-bindings/source-index slice shared across modules — analogous to #5867 shared `InternTable`. Targets `src/v1/stage0/src/v1_compiler_infer.rs:13998` (`seed_kernel_intern_table`) and `:11695` (`kernel_bindings_base`) inside `build_type_env` (intern TABLE already shared, `:11641`). This is v1-seed work and bank-if-cheap under the plan's discriminator (load-bearing: escalate before editing `build_type_env`).
- `Node.name: String` interning (item 5, bank-if-cheap) — lives in the v1 seed and dies with v1; keep it in item 5 and do not migrate it separately.

### Decidability framing (DESIGN §5/§6)

- Sub-moves i and ii are both RATCHETS gated on #5879 and landing in the v2/.dag realization. Ident u32-shrink and file-id side table are decidable representation changes; their `.dag`-authority path is gated on #5879, not independent of it. Kernel-slice sharing and empty-Vec verification are v1-seed work (bank-if-cheap, not root items).
- Sub-move ii (arena/u32 container) is priced in displaced cost (~3 GiB resident at width=1, DESIGN §6), NOT elegance. Guard the purity trap: the arena is the right call because it erases ~3 GiB of retained memory, not because it is elegant.
- Sub-move ii touches a load-bearing substrate type (the v2 Node model) and is operator-gated. It lands in the v2/.dag realization — not as a v1 seed rewrite. Caveat: field counts above are from the v1 .rs seed; confirm v2 representation at `src/v2/std/node.dag` before authoring the arena model there.
