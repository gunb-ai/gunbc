## Slice

This manager owns one lane: **`T-LaneE`** — complexity lens v2
parity via substrate-carrier-port
(`ROADMAP.md:47`, program doc at
[`docs/design-substrate-carrier-port-program.md`](../design-substrate-carrier-port-program.md)).

Size is **XL**; decomposed into five ordered sub-lanes

- **E-T** — port `DescentEvidence` + proof structure (**S**). No

- **E-C** — port `CallPattern` + lowering (**S**). Requires E-T.

- **E-M** — `MethodSemantics` port-or-subsume (**S–M**).
  Design-decision lane gated on T/C/I/P evidence.

## Framing question this manager answers

**Does v3's substrate carry the same descent/call/value/method
information v2 carried, well enough that complexity / cost /
idempotency / parallelism lenses can run on v3 authority without
Rust oracles?**

Today (per `docs/v3-lens-capability-register.md`):
- `complexity.dag` in v3 produces a single integer depth per port;
  v2 produces symbolic `CostExpr` / `SizeExpr` with work / span /
  certainty / asymptotic-class. Not equivalent.
- `cost.dag` is PROXY — no named size variables, Dimension wiring
  deferred.
- `idempotency.dag` is STUB — Rust oracle.
- `parallelism.dag` is STUB — fail-closed placeholder.

The ask from the thesis reward-structure framing: modeling work in
the language should pay back in compile-time facts *generated by
the language*. A Rust oracle is a runtime escape hatch in a lens
shaped like a compile-time proof. The slice's job is to move those
facts onto the v3 substrate so the lens is actually what it looks
like.

## Sequence + dispatch

- **Day 1.** E-T dispatches. No blockers. Port `DescentEvidence`
  carriers + lattice functions into v3-reachable
  `std/termination.dag`. Receipt: parse/lower/emit green; port-
  progress entry in the design doc.
- **After E-T lands.** E-C dispatches. Port
  `SizeBound` / `CallPattern` / `ShrinkFactor` /
  `IterationPrimitive` / `LoweringTarget` / `IterationDimension` +
  `lower_call_pattern`. Acceptance: `cost.dag` begins PROXY-partial
  progress.
- **After E-T + E-C land.** E-I dispatches. Tier 1 (structural) +
  Tier 2 (lattice) + Tier 3 (`CostBound` + master theorem).
  Pre-flight: verify v3 lowers `CostBound`'s self-referential-
  through-`List` shape.
- **After E-T + E-C + E-I land.** E-P dispatches. The design
  decision on attachment shape (on-substrate vs lens-derived vs
  side-table) happens here, not earlier; we need T/C/I evidence
  before calling it. Acceptance: v3 call produces
  `SubValueRelation` per-call readable by a lens; v2-oracle-vs-v3
  cementing test.
- **After E-P produces evidence.** E-M decision.

Sub-lane ordering is hard; **do not dispatch out of order.** The
design doc is the single authority on that — amendments to the
order go through the director.

## Hand-off points

- **Up to director.** Any proposal to add, remove, or re-order
  sub-lanes. The T → C → I → P → M order is committed scope.
- **Up to director.** Substrate design-questions that affect other
  managers — e.g., an E-M decision that proposes to relocate
  per-method metadata currently in `*_templates()` (the
  declaration-vs-template surface asymmetry row per
  `ROADMAP.md:354`). That choice has consequences for Surface and
  Testgen managers and should be a director-level coordination.
- **Sideways to Testgen Manager.** When E-P lands and v3 cells
  produce `SubValueRelation` per-call, the Testgen manager's
  `testgen_structural_coverage` gate predicate (`ROADMAP.md:65`)
  becomes evaluable against v3 authority rather than v2 oracle.
  Notify Testgen on E-P closure.
- **No downward dependency.** Substrate is a producer; other
  managers consume lens authority that this work unlocks.

## Unscheduled gaps relevant to this slice
