# Four PRs hand-edit a generated DESIGN.md, and the warning that would have stopped them lives in an arm that never runs

*2026-08-24. Findings assembled with deep-ant-102, who found the class and is one of the four; I am
another. **The class report itself is on hold** pending one control described at the end — what is
recorded here is what has been measured.*

## The class

DESIGN.md is a generated artifact. `dag/gunbc/generated_artifact.dag` maps
`DesignArtifact => "DESIGN.md"`, and `gunbc.design_document` emits it:

```dag
fn expected_design_md() -> String { serialize_markdown_source(doc: design_document()) }
fn design_drifted(committed: String) -> Bool { !(committed == expected_design_md()) }
```

Four open, mergeable PRs have **DESIGN.md as their only changed file**, with no change to any
authority. Every one of those edits is orphaned — the next regeneration emits from the `.dag` and
the sentence is gone.

```
#9098  app/gunbai-bot     (deep-ant-102)
#9085  app/gunbai-bot
#9056  briansrls          <- the operator
#9002  app/gunbai-bot     (mine)
```

`#9079` and `#8968` also edit DESIGN.md but edit `design_document.dag` alongside it. That is the
correct shape and they are **not** in the class. The class is four, not six.

## Why this is an affordance problem and not a discipline problem

**One of the four is the operator's own PR.** When the person who owns the repository makes the same
edit the same way, "tell people to be careful" is not a repair — the affordance is the defect. Four
independent parties produced identical outcomes, and the mechanism is fully explained:

**1. DESIGN.md carries no generated-by header.** It opens with `# gunbc — Design`. Every other
generated artifact announces itself — `extdeps_cargo.rs` opens *Generated by v1 compiler — do not
edit. Source module: extdeps.cargo.* Nothing in the file you are editing tells you a `.dag` owns it.

**2. The sentence that would have stopped all four EXISTS — in an arm that never executes.**
This is the sharp part. `dag/tools/generated_artifact_gate.dag`:

```dag
let reason = if all_ok { "" } else {
  concat(
    concat("generated-artifact drift/validation failed: ", first_failing_diagnostic_path(...)),
    " — it is a GENERATED projection of its .dag authority; do not hand-edit, regenerate via
      main_wet on dag/tools/generated_artifact_gate.dag"
  )
}
```

The warning is not a header on the artifact. It is the **drift gate's failure diagnostic**, so it
reaches a human only when the gate runs *and* fails. And DESIGN.md's own Building-&-checks section
lists the generated-artifact drift gates among the things left **UNGUARDED** by the floor cut.

So the complete chain is:

| step | state |
|---|---|
| does the artifact say "do not hand-edit"? | no — no header |
| does anything else say it? | yes — the drift gate's failure message |
| does the drift gate run? | **no** — unguarded since the floor cut |
| result | hand-editing is silent, CI is green, review sees a prose diff and approves |

The repository already contains the correct sentence. It is placed in the one arm that a deleted
gate makes unreachable. That is a stronger and more actionable finding than "DESIGN.md needs a
header", because it locates an existing authored intention that a cut silently disabled.

## What is measured, and what is not

**Measured.** The emit relation, from source. The file lists of all six PRs. That DESIGN.md has no
header. That the warning is a gate-failure diagnostic rather than an emitted line. And that a
**repo-built** `gunbc` resolves `design_document.dag`'s closure and computes the document — my run
returned the document's own prose inside a refusal whose cause was a return-type contract
(`expected_design_md` returns `String`; `gunbc run` requires the entry's result to carry a
`ProcessExit`), not a resolution failure.

**NOT measured, and it is the whole framing.** deep-ant-102 ran the documented recipe
(`main_wet` on the gate) and it exited 1 against a wall of unresolved names — `fold not found in
scope`, undefined `Empty`, unresolved `DissolutionCondition`, `RoadmapNode`, `DispatchLiveSession` —
**identically on unmodified main**, so it is not anyone's edit. The open question is whether the
RECIPE is broken or the BINARY is stale: `gunbc` in that environment resolves to a pinned
`/usr/local/bin/gunbc` via `GUNBC_V2_COMPILER`, not to anything built from the corpus, and a pinned
tool predating current sources would produce exactly those errors.

That distinction decides the whole report and points at different owners:

- **If the gate works under a repo-built binary:** the documented regeneration recipe names a tool
  the environment resolves to a stale pin. The correct route *appears broken to anyone who tries it*,
  which explains four orphaned PRs — including the operator's — better than the missing header does,
  and the header fix is then secondary.
- **If the gate fails under a repo build too:** the regeneration route genuinely does not work on
  main, and that is larger than anything else in this document.

Two dispatches are running this discriminator independently. **Nothing above should be raised as a
recommendation until one returns.**

## Two corrections already absorbed, recorded because they were nearly load-bearing

deep-ant reported that the gate *wrote* to DESIGN.md while failing, and that their sentence was
absent from what it wrote. Their own control refuted both: the gate writes nothing in either arm;
what they read as gate output was the remote runner showing **their own patch** in its diff, because
`ctrl-build` ships the worktree as patches — and the grep returned zero because they had reverted
DESIGN.md before dispatching. An instrument reported its own input back as its output.

That is the same shape as my bazel-label grep earlier today (`instrument-traps-2026-08-24.md`, trap
14a) and it is worth naming as an environmental hazard rather than a lapse: **a remote runner
mirroring your worktree and a local tree you just edited are indistinguishable in a diff.**
