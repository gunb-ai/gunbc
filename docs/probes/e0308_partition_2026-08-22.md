## Raw rows → canonical sites

- **128** — raw `error[E0308]` blocks (what the probe histogram counts).
- **154** — canonical mismatch sites.

Blocks < sites because one `arguments to this function are incorrect` block carries one
`expected …, found …` per wrong argument. Two collapses run the other way and both are *unit*
corrections, never deltas:

1. **One mismatch printed two ways.** rustc's caret label elides deep generics
   (`Coverage<Rc<...>>`) while the block's `= note:` prints the same type in full
   (`Coverage<Rc<CoverageDefectAcceptanceKey>>`). Counting both inflates 13 coverage sites to 26.
   The classifier drops an elided pair only when a non-elided pair in the *same block* matches it
   under `... → .*`.
2. **One type printed two ways.** `im::Vector<T>` and `Vector<T>`, `std::string::String` and
   `String` are one type; module-path noise is normalized before dedup.

Sites are keyed on `(file, line, col, {expected, found})` — the pair is direction-insensitive,
because rustc prints both orientations of one mismatch when it reports a closure's argument and
its expectation.

## The keying ruling — precedence declared, not emergent

The first partition summed to exactly 154 and I cited that sum as evidence it was total with
nothing double-counted. **It was total, and the sum is exactly the check that cannot see what was
wrong with it.** Two reviewers ran the rule in the direction I had not: which *non*-R1 sites pass
the R1 test. Two do, and the mechanism behind them is general.

The arms use **three different keying schemes**, and every arm keyed on a *carrier* sat above
every arm keyed on a *delta*, so the carrier silently won every collision by source order:

| scheme | fires on | arms |
|---|---|---|
| delta-keyed | the shape of the difference | R1, A-clone, BOX-WRAP, ELEM-COLL, D |
| carrier-keyed | the head type's identity | B3, B2, T2, T3, DIAG, C, R2 |
| context-keyed | the constructor descended through | W |
| message-keyed | rustc's own text | ARG-ORDER |

**The ruling, in three parts:**

1. **An exact delta test outranks a carrier test.** If erasing every `Rc` from both sides makes
   them equal, the sides *agree* about the carrier and disagree only about wrapping, so the
   faulty decision is the wrap decision — naming the carrier would name a fact both sides already
   share. R1's test is the one exact delta test that can collide with a carrier arm, so R1 is
   hoisted above them. `Witness<Rc<DeterminismFact>>` vs `Witness<DeterminismFact>` and
   `Witness<Rc<TerminationProof>>` vs `Witness<TerminationProof>` therefore move **W → R1**.
2. **A carrier arm keys on the carrier at the difference, not at the head.** The head of
   `Outcome<Option<Rc<Node>>>` vs `Outcome<Rc<Node>>` is `Outcome` on both sides and says nothing
   about the disagreement, which is an `Option` presence one level down. The discriminator now
   descends to the first differing position; the site still reports its outer pair.
3. **W is context-keyed and sits below the carrier arms.** Its row means "the two sides agree the
   value is a `Witness` and disagree about what it witnesses". A difference that is *itself* a
   carrier fork — a unit collapse, a text carrier — is named by the fork, not by the constructor
   it happens to sit inside.

**The R1 rule defect that started this** (reported by `royal-dove-436` with a tested fix, and
confirmed independently by `smart-ram-730` with a self-tested eraser): the old arm admitted a site
whenever the substring `Rc<` occurred *anywhere* on either side, which is not evidence that the
**delta** is an `Rc` wrap. The `rc_erased` eraser is balanced-bracket and recursive, with its
self-test asserted at import time — a regex on `[^<>]*` leaves `Rc<Refined<Artifact>>` untouched
and would report a real R1 site as unequal. A contributing cause is fixed with it: the delta
vector's optionality axis tested the head only, so an `Option` nested inside `Outcome<_>` never
set the flag.

**Where the seven leavers went, each verified against the TSV:** 2 → R2 (`Option` presence inside
`Outcome`), 1 → ELEM-COLL (an extra `Vector` nesting layer), 1 → C (`Vector<()>` vs
`Vector<ComplexityLowering>`), 3 → D (`Measure<(), S, Rc<i64>>` vs `Measure<(), _, i64>` — a
type-parameter binding, `()` vs `S` vs `_`, at generic-argument position; that call was mine to
make and D is where a generic-argument disagreement belongs).

**One off-branch consumer, flagged by `royal-dove-436` and now safe by construction:** an R1
experiment uses `v2_lens_cost.rs:312`/`:315` (`Rc<Nat>` vs `Nat`) as a rejection control, which
sat in R1 only because B3's arm requires one side in `NUMERIC_NATIVE` and `Nat` is not in it — so
a later broadening of B3 would have silently deleted their control. Under ruling (1) those sites
are R1 because the delta test is exact, whatever B3 later admits.

## Carrier flags — evidence beside the root, not a fifteenth category

A cluster is keyed on **what the difference is**. Some facts that matter for *costing* are
properties of the emitted **declaration** instead, so they are not decidable from the pair at all —
and an arm keyed on a cause the classifier cannot see is a guess wearing a category's name. Those
facts are therefore carried in their own TSV column, joinable across clusters, exactly as the
callee note is.

The live instance, reported by `royal-dove-436` (2026-08-22): `std.measure`
`billing_month_as_hour_count_representation_note` records that stage0 alias emission collapses
applied-generic `Measure` aliases to a concrete all-unit parameter list while `fn`/`data` return
sites still reference the un-erased alias params, and carries its own dissolve-on. Six sites in
this partition sit on that carrier, and they are split across two clusters:

| flag | sites | clusters |
|---|---:|---|
| `generic_params_unit_on_both_sides` | 4 | R1 4 |
| `generic_param_unit_on_one_side` | 2 | C 2 |
| `generic_params_unit_on_both_sides+generic_param_binding_differs` | 1 | D 1 |
| `generic_param_binding_differs` | 1 | D 1 |

**Why this is a flag and not an arm, stated precisely because the suggestion was to make it an
arm:** at `std_cache_interface.rs:652`/`:667` the collapse is present on **both sides**
(`Measure<(), (), i64>` vs `Measure<(), (), Rc<i64>>`), so the delta there is purely the `Rc` and
the erasure is *invisible in the mismatch*. No pair-keyed rule can recover it; only the declaration
can. Checking a collapse arm *before* the delta rules — the suggested handling — would also invert
the keying ruling above and re-split R1 by a property that is not its delta. The flag gets the
result the suggestion was after (the rows pool by cause, so nobody costs the defect twice or
designs a repair for a class whose dissolve-on is already registered) without minting a category
whose defining fact the classifier cannot see.

**What is not claimed:** that the alias path *causes* the collapse. The evidence is the in-corpus
note plus a shape match on these rows; the producer of each declaration was not traced in this run.

**One competitor eliminated, by `royal-dove-436`'s trace (2026-08-22), which narrows the field
without closing it.** The obvious rival explanation for the opposite-looking directions at
`cache_interface` versus `realization_*` was a *forking wrap policy* — producers disagreeing about
whether `Nat` is shared. It is not forking: `Nat` is in `shared_types` at all 8 producers that
consult it, in type and value position alike, and `Int` at none, with a behaviour-preservation
control (traced and untraced emission byte-identical). So the direction split must come from
upstream of the wrap decision, which is exactly where the documented alias-collapse path sits. That
trace answers the wrap predicate, **not** which emitter produced each declaration, so the cause row
above stands as note-plus-shape-match rather than being upgraded.
