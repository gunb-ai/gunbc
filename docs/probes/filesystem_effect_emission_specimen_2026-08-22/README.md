## Is this still true? — how to tell

`.emitted` keeps these files from being *consumed*. It does not keep them from being *believed*, and
a recorded emitter output is exactly the artifact that gets re-read later as a current claim. So:

| axis | value |
|---|---|
| captured | **2026-08-22** |
| source tree | `993163ae32` on `session/royal-dove-436-census` (merge base `d72ffe8708`) |
| emitter | `v1-compiler` `claim_executor --required-regen`, built from that same tree |
| subject module | `src/v1/tests/claim/carrier_realization_census.dag` — **deleted**, see the probe doc |

**This describes the emitter's behaviour on 2026-08-22 and makes no claim about any later tree.**
The defects it records are properties of the emitter, not of the deleted census module — that module
was only the occasion — so they are expected to reproduce from any source exercising the same
`Filesystem` surface. Anyone relying on them should re-emit against current `main` and compare
rather than cite these bytes as present-tense. If the two disagree, **these files are the stale
side**, by construction.
