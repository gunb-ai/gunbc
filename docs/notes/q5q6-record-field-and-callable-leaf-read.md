Q5(a) v1.compiler.infer callable_component_ground_mismatch
- Compares: formal_part (the DECLARED callable's param/return type) against instantiated = substitute_generics(actual_part, subst) (the PRODUCED callable's matching part, generics bound by callable_signature_substitution from the produced side only). Reached via callable_signature_mismatch -> callable_arrow_mismatch, itself reached only from callable_inhabitance_mismatch, which declared_type_inhabitance already calls (InhabitanceRefused RefusedCallableMismatch), plus the 3 direct callers (record field, direct_call_arg_type_mismatch, callable_element_signature_mismatch).
- So the arrow-vs-arrow structure is ALREADY inside the inhabitance relation; the site in question is its LEAF: for two non-arrow parts it does !node_type_compatible(formal_part, instantiated, TextJudgedIn env), and ONLY when BOTH are conformance_ground_type (kernel-ground); otherwise false (unjudged). If exactly one side is an arrow it refuses outright when either side is ground.
- Symmetric or directional: the leaf call is node_type_compatible, a symmetric-in-shape compat (container/alias/opt/unit/typevar arms, left_err|right_err|tv => true). Orientation is the SAME for params and return (formal_part=declared, actual_part=produced both times), i.e. invariant: params are NOT compared contravariantly. A true inhabitance question for a callable is directional: produced fn must accept every declared param (declared param inhabits produced param) and return something that inhabits the declared return. That is the real directional/semantic gap, and it is independent of which leaf relation is used.
- ROUTE or REASON: neither is stated at the site. The leaf takes TypeEnv, not InferScope, and declared_type_inhabitance takes an InferScope (it reads scope.type_env.source_indices and the scope for refinement/nominal arms), so routing needs the scope threaded through callable_signature_mismatch/callable_arrow_mismatch and its 4 callers; that is a signature change, a REASON that is checkable, not a stated one. The ground-only gate means the leaves are kernel types only; for kernel-ground pairs I expect compat and inhabitance to agree except declared_realizes_as_kernel_numeric / numeric widening and alias-of-kernel arms. I did NOT find a divergence by reading; claiming one would be inflation.
- Discriminating RED (candidate, needs a differential run first): enumerate the ground-leaf population (callable_signature_mismatch calls over the corpus) and run both node_type_compatible and declared_type_inhabitance on each (declared=formal_part, produced=instantiated); the set where compat=true and inhabitance=Refused* (or reverse) is the RED population. If empty, (a) is a NO-OP route change and the honest disposition is REASON (leaf is ground-kernel only; relations agree on it) with the contravariance gap filed separately. Candidate source cells, in the dag/test/claim/infer_callable_type_argument_witness.dag style (source string through gunbc.compile_census_probe, assert blocking rows): declared param fn(Nat)->Int fed fn(Int)->Int (contravariant OK; invariant compat refuses/admits depending on kernel-grounded carrier arm), and fn(Int)->Nat fed fn(Int)->NonNegativeInt (return-position alias of a kernel-grounded carrier: produced_is_kernel_grounded_carrier_or_its_alias Inhabits, node_type_compatible may not). Q5(b) infer_record_lit_structural field_declared_type / field_conformance_type

So a produced type that is incompatible but matches none of the five local arms is silently ACCEPTED. node_type_compatible here is a skip, not a judgment.
