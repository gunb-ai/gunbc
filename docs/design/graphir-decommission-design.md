# GraphIR Decommission Design (DSL-Only Authoring)

**Date:** 2026-02-22  
**Status:** Draft (design gate before deletion work)  
**Scope:** Replace handwritten GraphIR authoring with canonical `.dag` DSL modules.

---

## 1. Problem Statement

The repo is in a mixed state:

- DSL modules exist for many workflows/services.
- Multiple runtime entrypoints still execute handwritten Rust graph builders and handwritten ops stacks.
- The lowering/resolution bridge still permits fallback behavior that masks incomplete migration.

This document defines an exhaustive inventory and a deletion-first migration plan to get off old handwritten GraphIR authoring code.

---

## 2. Goal and Non-Goals

### Goal

Make DSL the only authoring surface for workflow/service topology and remove old handwritten graph-authoring code paths.

### Non-Goals

- Do not delete compiler/runtime foundations required to execute DSL today (`core/daglang`, `core/exec`, `core/ir`, transport runtime).
- Do not preserve compatibility shims longer than necessary; this repo is non-prod and prefers fast cutover.

## 4. Root Causes Blocking Full DSL Ownership

### R1. `dsl_module` metadata still routes to handwritten builders

Evidence:

- `lib/tools/gist/src/lib.rs` (`builder = "build_gist_graph"`, `dsl_module = "gist"`)
- `lib/tools/deps/src/lib.rs` (`builder = "build_deps_graph"`, `dsl_module = "deps"`)
- `lib/tools/clippy/src/lib.rs` (`builder = "build_clippy_graph_lint_all"`, `dsl_module = "clippy"`)
- `lib/review/src/lib.rs` (`builder = "build_diff_review_graph"`, `dsl_module = "review"`)
- `gunbc-dag/src/dag_viz/mod.rs` (`builder = "build_dag_viz_graph"`, `dsl_module = "dag_viz"`)

### R2. Interactive/external semantics are not fully carried from DSL to runtime

Evidence:

- DSL marks external interactive shell ops (for example `dsl/services/shell.dag`, `dsl/tools/dag_viz.dag`).
- Lowered service triplets force `is_interactive: false` (`core/daglang/daglang-lower/src/lib.rs` around transport node construction).
- Generic shell prepare creates `ShellRequest` without applying DSL interactive/external semantics (`gunbc-dag/src/resolve_service.rs`).

### R3. Resolver still allows permissive passthrough

Evidence:

- Default passthrough in `gunbc-dag/src/resolve.rs`.
- Tests codify fallback for unknown modules/callables in `gunbc-dag/src/resolve.rs`.

### R4. Workspace composition still has manual Rust adapters for legacy stacks

Evidence:

- Manual subdags for gist/deps/clippy/dag_viz/testgen in `gunbc-dag/src/workspace/subdags/`.
- Handwritten tool graphs still imported from library crates.

### R5. Existing coverage checks are necessary but insufficient

Evidence:

- Codegen coverage checks ensure module presence and target mapping (`gunbc-dag/src/bin/codegen_cli.rs`) but do not enforce execution route correctness (DSL builder vs handwritten builder).

---

## 5. Target Architecture

1. `.dag` files are the only source of topology truth for tools/pipelines/services.
2. Runtime builders are thin DSL compilation wrappers only (`build_*_graph_dsl()` style).
3. Service transport behavior (including interactive/external) is derived from DSL annotations and respected at execution.
4. Resolver is fail-closed for unknown callables; no default passthrough escape hatch.
5. Legacy handwritten graph files are deleted once their DSL execution routes are live.

---

## 6. Migration Plan (Deletion-First)

## Phase 0: Freeze and Gate

- Freeze new handwritten `*graph.rs` authoring for tools/services.
- Require any new workflow/service topology to land in `dsl/` only.
- Add CI check for `#[tool_target(... dsl_module = "...")]` entries:
  - Builder/import must be DSL-backed (directly or through a thin wrapper).

## Phase 1: Route All DSL-Tagged Tools Through DSL Builders

- Cut over `gist`, `deps`, `clippy`, `review`, `dag_viz` target registrations to DSL-backed builders.
- Update workspace subdag composition to use DSL-backed builders for those modules.
- Verify parity with existing generated tests/contracts.

## Phase 2: Fix Interactive/External Model Gap

- Carry service operation interactive/external semantics from DSL lowering into runtime metadata.
- Ensure shell prepare sets `ShellRequest.passthrough = true` when modeled as external/interactive.
- Keep progress renderer paused during passthrough (already implemented in executor/display path).

## Phase 3: Delete Legacy Tool Graph Authoring

- Delete legacy tool graph builders and associated graph-mock stacks once Phase 1+2 are green.
- Delete manual workspace subdag adapters that only exist for legacy graph stacks.
- Remove fallback tests that require unknown-module passthrough behavior.

## Phase 4: Cloud/Provider Domain Decision (Migrate or Drop)

- For non-critical providers (AWS/Azure) choose one:
  - Drop now (delete handwritten stack).
  - Or add DSL equivalents, then delete handwritten stack.
- For GCP/cloud/LLM/review domain stacks:
  - Migrate semantics to DSL services/patterns + generic interpreters.
  - Delete handwritten graph and ops files after parity confirmation.

## Phase 5: Fail-Closed Enforcement

- Remove resolver default passthrough for unknown callables.
- Add CI guardrails:
  - Reject unresolved callable fallbacks.
  - Reject `Replaces:` claims whose target files still exist past migration wave.
  - Reject `dsl_module` targets that do not compile/resolve from DSL.

---

## 7. Acceptance Criteria (Definition of Done)

The migration is complete when all are true:

1. No active tool/pipeline registration routes through handwritten graph builders.
2. No legacy handwritten authoring files remain in delete-target categories (see inventory).
3. Resolver fails closed on unknown modules/callables.
4. Interactive/external DSL semantics are reflected in runtime shell passthrough behavior.
5. CI enforces all above constraints.
