## §1. Policy frame (operator flavor (iii))

Operator decision 2026-05-30 (relayed via PM): the Jun 1 release ships under **flavor (iii)**:

1. v4 substrate ships **in-tree** (per-surface table below names which subtrees).
2. v4 is **advertised as a compile target** in user-facing docs (README, SUPPORTED.md, release notes).
3. The advertisement is **conditional**: it stands only if Wave 1 + Wave 2 close by Jun 1.
4. If Wave 1 + Wave 2 do **not** close, v4 falls back to **fail-closed**: the public README states v0.1.0 ships v2 substrate + v4-modeled-not-shipped, with a **named v0.1.1 fast-follow commitment date** carrying the deferred v4 advertisement.

The two-axis vocabulary maps onto this frame:

| Public surface state | `ship_disposition` (this lane) | `engineering_state` (this lane) |
| -------------------- | ------------------------------ | ------------------------------- |
| Shipped + advertised | `PROVEN` | `EXECUTABLE_RECEIPT_PRESENT` (the per-surface receipts named in §2 hold) |
| Shipped as substrate-only (in-tree, not advertised as runnable) | `PROVEN` (via substrate-as-data) | `SUBSTRATE_PRESENT` |
| Modeled-not-shipped (stripped from public snapshot) | `GAP` | one of `SUBSTRATE_PRESENT` / `SCAFFOLD_PRESENT` / `PARTIAL_GATE_PRESENT` |
| Explicit out-of-scope for v0.1.0 by operator decision | `NOT_IN_V4_v0_1_0` | n/a |

**Fail-closed transition rule:** when an advertised-as-runnable surface (row 1 above) loses its receipts (e.g., the per-PR runner breaks, or the Wave-1/2 exit condition the advertisement depends on slips), the surface is **automatically demoted** to row 2 (substrate-only) for the v0.1.0 tag; the v0.1.1 fast-follow named-commitment-date inherits the advertisement.
