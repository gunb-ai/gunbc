# daglang v0.1.0 — first public release

A language for programs as dependency graphs, with a compiler (`gunbc`) that
emits to Rust, Python, Go, and back to `.dag`. If it compiles, the declared
intent is structurally sound inside the modeled system; external reality not
carried in the graph (a REST endpoint that's down, a database that's
unreachable) remains outside that guarantee — gunbc generates tests for those.
See [THESIS.md](../../THESIS.md).

This is the seed release: the v2 self-hosted pipeline is real and tested;
the v4 substrate is in active migration; distribution polish is deferred.
The table below is the honest version of "what works."

## Quick start

```bash
git clone https://github.com/gunb-ai/daglang.git && cd daglang
cargo build --release -p v2-compiler --bin gunbc

./target/release/gunbc compile \
  --source-root dsl/examples/weather \
  --source-root dsl/std \
  --output-dir /tmp/weather-out \
  --target rust

cargo check --manifest-path /tmp/weather-out/Cargo.toml
```

The source is [`dsl/examples/weather/weather.dag`](../../dsl/examples/weather/weather.dag):
domain types, a coproduct (`Condition = Sunny | Cloudy | Rainy | Snowy`),
pattern matching, and list pipelines. `gunbc` emits a self-contained Rust
crate; `cargo check` succeeding is proof the emitted code is well-typed with
zero hand glue.

Swap `--target rust` for `python`, `go`, or `dag` to retarget the same source.

## What this release is not

- Not a binary distribution. `install.sh` is modeled but not yet emitted;
  package-manager channels (Homebrew, deb, apt) are planned, not shipped.
- Not the v4 substrate as production. v4 is the direction of travel; v2 is
  what compiles your code today.
- Not feature-complete for execute-verified test runners across every target.
