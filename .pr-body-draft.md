# One declaration per operation, keyed by its declaration path (M2V two-keyings + D16 part 1)

Discharges the one modeling obligation both tracks of the demand-engine program name
(`gunbc.plans.demand_engine_program`, M2V "Population and effects" / §7.1 D16(1)): every operation
declares its execution semantics and access shape AT ITS DECLARATION, keyed by its declaration
path — the same key D13 (`v2.compiler.dependency_demand`) already uses for its resource
requirement. The two keyings of one concept (operation identity) become one; the slug-keyed
hand rosters are deleted in this change (DESIGN 3, delete-first).

## What lands (model first, consumers, then the deletion)

1. **Seams + projection rows** (`dag/std/primitive_projection.dag`, the six host-boundary `fn`s at
   their homes): each of the six corpus-fact operations gets a seam declaration and a
   `HostRealizedSeam` projection row, following the `decl_facts` / `symbol_lexeme` precedent
   exactly (self-call body, row added in the same commit, signature matching the v1 builtin's
   arity and types in `src/v1/04_method.dag`).
2. **D13 seam opacity** (`src/v2/compiler/dependency_demand_census.dag`): a declaration projected
   `HostRealizedSeam` is an OPAQUE operation to the demand engine. It becomes an `OperationFact`
   whose requirement comes from its declaration row; **its self-call body is never walked**; a
   seam with no row is the typed `RequiresUndeclared` arm and BLOCKS — never a default, never a
   silent `RequiresNone`. This closes a live fail-open measured on main: `decl_facts` (and every
   seam) settled `DemandDerived{empty}` through its self-call body — a host observation read as
   pure.
3. **The declaration module** (`src/v2/std/operation_declaration.dag`, new): one row per opaque
   operation keyed by `std.decl_ref.DeclarationRef`, beside `std.primitive_projection` (the
   corpus's only "host-realized" authority) and joined to it on the same key. Each row carries
   requirement, `PrimitiveExecutionSemantics`, `EffectOperationDisposition` (with its
   `blocking_question` — the six fact operations keep KNOWN `ObservesHost` semantics and their
   OPEN disposition; the open question stays on the disposition channel, never the semantics
   channel) and `DeclaredAccessShape` — `std.effects.EffectShape` or the typed
   `AccessShapeNotYetDeclared`, which blocks. The slug-keyed rosters' data survives only as a
   VIEW over these rows (`effect_demand_operation_classifications()`), so the M2V census reads
   declarations by path and its blocked/implementable derivations are untouched.
4. **Consumers** read the declaration by path:
   - `v2.compiler.effect_pair_census`: the `OperationSemanticsIndex` keyed by primitive-identity
     slug (a key that matched NO walked, module-qualified path) is gone; reach reads each reached
     operation's row at its own `QualifiedName`; an operation keyed by more than one row is
     ambiguous → Unknown, counted, never guessed.
   - `v2.compiler.effect_demand`: blocked/implementable derive from DISPOSITION on the
     declaration rows, as before — the honest 1/6 census stands, claimed, unchanged.
   - M2V effect-free admission: same route (disposition), same derivations.
5. **Deletion**: `src/v2/compiler/primitive_execution_semantics.dag` is removed; both claim files
   import the new home. No parallel authority: the declaration module's population is claimed
   BIJECTIVE with `std.primitive_projection`'s `HostRealizedSeam` population in both directions,
   over the projection's own enumerated rows (27:27 — a rebase-time dead row for the seam main
   retired in #15158 was caught by exactly this control).

## PREDICTION, written before the run (the seam-opacity flip, measured not narrated)

Seam rows carry 13 × `RequiresResources{Filesystem}` and 14 × `RequiresNone`.

- Every TRANSITIVE caller of the 13 Filesystem-required seams changes D13 arm
  `DemandDerived{empty}` → `DemandDerived{Filesystem}` (the fold joins the seam's `OperationFact`
  requirement at the callee edge). Callers of the 14 `RequiresNone` seams stay
  `DemandDerived{empty}` — no flip, correctly (pure kernel seams).
- Reach-side: walked operations that ARE seams move from `unclassified` (the slug index matched
  no walked path) to their declared semantics (`ObservesHost` → `ReachesHostObservation`), so B0
  pair counts should be stable (unclassified reached conservatively both ways); the semantic
  distinction is now keyed correctly.
- M2V admission: blocked/implementable counts (1/6) do NOT move — by design, they derive from
  disposition and the six fact operations' dispositions are carried unchanged.
- The delta is measured as CLAIMS at both heads: `v2.test.claim.compiler.seam_fail_open_delta`
  asserts the OLD arms (body walked into a FunctionFact; caller settles Derived{empty}) and is
  GREEN at the measurement head (origin/main + harness, `measurement/seam-fail-open`) and RED at
  this head; `v2.test.claim.compiler.operation_declaration_seam` asserts the NEW arms (row's
  requirement by `DeclarationRef`, no FunctionFact for the seam, caller settles
  `Derived{Filesystem}`) and is RED at the measurement head and GREEN here. A caller flipping is
  correct; no expectation was edited to stay green.

## Controls

- **RED A (discriminating)**: deleting `filesystem_read`'s row turns the census claim red through
  the BLOCKING arm (`RequiresUndeclared`, asserted as an arm — never `RequiresNone`), and the
  projection-bijection claim names the seam-without-a-row. An operation with no declaration
  refuses; proven by deletion, not assertion-of-absence.
- **RED B**: `pure_and_bound_input_semantics_do_not_reach_holds` +
  `an_operation_with_no_semantics_row_is_unclassified_and_reaches_holds` — no fabricated Pure and
  no fabricated `ReadEffect` for a missing row.
- **INHABITANCE (pairing obligation, DESIGN 3)**: the claim runs the REAL producer — the
  instrument's own route (`native_test_context_from_ingest` → `native_test_resolve_module` →
  `demand_census_module_facts`) over the real `std.data_index` closure bytes read from disk — and
  matches the walked seam at its module-qualified path to its `DeclarationRef` row
  (`RequiresResources{Filesystem}`), forms NO FunctionFact for the seam (body never walked), and
  settles a transparent caller at the row's requirement through the real `dependency_demand_of`
  fold. The deleted slug index could not pass this: the slug equals no walked path.

## Obligations named, not minted (D16 part (3))

Metadata read has no `EffectShape` arm and `ExecuteEffect`'s footprint is opaque: carried as the
typed `AccessShapeNotYetDeclared { reason }` on the rows that need it
(`manifest_read_has_no_effect_shape_arm_d16_part_3`), which BLOCKS. No new arm was minted — the
existing coproduct carries the distinction honestly.

## Surface clause: deliberately absent

No `semantics`/`effect` surface syntax in this PR: v1 parses `requires` itself
(`src/v1/02_parse.dag`, the `modifier_props` branch) and is semantics-frozen under the purpose
test (`gunbc.v1.v1_seed_standing`). Transparent bodies owe no declaration anyway — their facts are
DERIVED from the closure (D13; §2.4), and an authored semantics/shape on a transparent body is the
anti-pattern this design refuses. The declaration is owed only at OPAQUE boundaries (host-realized
seams, capability members with no body). A capability/service surface clause is a later change
whose trigger is the v1 parse edit; the keyword census was done (`semantics`, `effect` reserve
nothing new beyond `input`, already reserved).
