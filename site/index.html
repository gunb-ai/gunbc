Most production bugs are glue bugs

Modern software is 10% business logic, 90% orchestration glue — wiring APIs, managing credentials, retrying on failure, keeping state consistent across services, making sure the Go SDK does the same thing as the Rust SDK.

That glue is where bugs live. The API returned a 429 and your retry logic had an off-by-one. The credential expired mid-request. The state machine crashed between "wrote the file" and "updated the ledger." Every framework — Terraform, Temporal, LangChain — tries to manage this complexity at runtime. They all still require you to hand-write the glue.

What if glue didn't exist? What if you declared the contract and the compiler generated correct orchestration for every target language — with crash-safe state, structural soundness, and obligation-driven tests — by construction?

One compiler. Three frameworks eliminated.

Terraform, Temporal, and LangChain solve the same underlying problem — declarative intent compiled to correct execution — but they're three separate runtime frameworks, each with their own glue surface. gunbc is a compiler that subsumes all three.

The key difference: these frameworks are runtime systems that require you to write glue in a host language. gunbc is a compiler — you declare the workflow, it generates the correct implementation. The glue doesn't exist because the compiler produces it.

How it works

Define services, workflows, and pipelines in .dag files. The compiler produces typed, transport-correct implementations in every target language from a single definition.

Define once

service github.Issues {
  @endpoint("https://api.github.com")
  @auth(BearerToken)

  operation Get {
    input  { owner: String, repo: String, number: Int }
    output { title: String, state: String, labels: List<String> }
    @rest(GET, "/repos/{owner}/{repo}/issues/{number}")
    @idempotent @readonly
  }

  operation AddComment {
    input  { owner: String, repo: String, number: Int, body: String }
    output { id: Int, url: Url }
    @rest(POST, "/repos/{owner}/{repo}/issues/{number}/comments")
    @idempotent
  }
}

Worked example: autonomous software delivery

The hardest glue problem we could find: a multi-stage, stateful, agent-orchestrating pipeline that takes a GitHub issue from idea to merged code — autonomously. We built it with the compiler to prove the approach works on a real, complex system.

The pipeline

idea→ design→ review→ accepted→ implement→ code review→ testing→ done

Each stage transition is a claim-guarded, idempotent, crash-safe operation. The pipeline is defined in ~550 lines of .dag — no Rust, no Go, no YAML.

Three-layer abstraction

Business logic never touches infrastructure. The compiler resolves bindings at compile time via deployment profiles.

1 Pipeline Pure domain operations. "Discover issues." "Acquire claim." "Record outcome." No mention of REST, GCS, or file I/O.
2 Interfaces Typed contracts: IssueProvider, ClaimStore, OutcomeLedger, AgentProvider. Provider-fungible — same pipeline, different backends.
3 Implementations Concrete providers selected by profile. Local: file-based state. Cloud: GCS with CAS. Test: in-memory stubs. Same compiled pipeline. 
profile local {
  bind IssueProvider  -> GitHubIssueProvider { owner: "gunb-ai", repo: "gunbc" }
  bind ClaimStore     -> FileClaimStore     { dir: env("SDLC_LEDGER_DIR") }
  bind AgentProvider  -> CodexAgentProvider
}

profile cloud_run {
  bind IssueProvider  -> GitHubIssueProvider { credential: secret("github-token") }
  bind ClaimStore     -> GcsClaimStore      { bucket: "sdlc-claims" }
  bind AgentProvider  -> CodexAgentProvider  { credential: secret("codex-api-key") }
}

Structural guarantees

These aren't features you opt into. They're properties the compiler enforces. If it compiles, they hold.

Transport boundary enforcement
All runtime I/O goes through explicit transport nodes. Direct file/network access is banned by the compiler. Business logic is pure by construction.
Multi-language correctness
One .dag definition produces identical semantics in Rust, Go, and C. No hand-maintained SDKs. No cross-language drift.
Obligation-driven testing
The compiler determines what's provable statically and generates tests for everything else. Execution, contracts, scenarios, and resource lifecycles — covered automatically.
Crash-safe state management
State transitions follow a fixed ordering with replay-skip, CAS claims, and reconciliation. Crash at any point, resume without repeating side effects.
Compile-time dependency injection
Deployment profiles bind abstract interfaces to concrete implementations at compile time. Same pipeline, different backends — local files, GCS, in-memory stubs.
Structural soundness
Acyclic, type-compatible, cardinality-compatible, and sub-DAG interfaces match. If it validates, it is sound. No runtime type errors.
