## Expected effects

- `enable` re-creates the unit's `paths.target.wants` symlink; `--now` arms the path watch.
- If a watched directory is already non-empty, systemd IMMEDIATELY starts the triggered `.service`.
- That service runs the installed `bin/gunbc`, which after J2 is the witnessed r2 binary, under its own installed unit file.
- Through the belt tick this runs M4 (`belt_session_settlement_pass`; operator G1 "yes") over the moved attempt state, with the
  slots cutover OFF by r2's construction.
- Such runs are system units outside any keeper scope, bounded only by their own unit limits.

## Pre-state (read-only, exact `--value` comparisons, before the first enable)

1. Each `.path`: `LoadState=loaded`, `UnitFileState=disabled`, `ActiveState=inactive`, `Triggers=` the expected service.
2. Each triggered `.service`: `ActiveState=inactive`.
3. Each triggered `.service`'s installed limits: `MemoryMax` and `RuntimeMaxSec` are present. If either is absent, J3
   refuses. This is a fresh read of the unit file sha, ExecStart, MemoryMax, RuntimeMaxSec and User; per J3-PLAN (G-a) it is
   authorized only as part of J3's own decision.
4. The `.path` units' `TriggerLimitIntervalSec` and `TriggerLimitBurst` are recorded.

## Readback (after each unit's enable)

- `ActiveState=active`, `UnitFileState=enabled`, `Triggers` unchanged.
- `InvocationID` and `ActiveEnterTimestampMonotonic` are read; these go into the receipt.
- For 10 minutes, every 30 s, read the triggered service's `Result`, `ExecMainStatus` and `NRestarts`.
- On any mismatch or non-success:
  - run the failure act on THAT unit only, then read back `inactive`/`disabled`;
  - leave the triggered service's own run to its unit bounds;
  - write no receipt for that unit;
  - K2 is not run.

## Receipt (consumed by K2, which replaced J4)

A file with EXACTLY three lines, one per unit, each exactly:

    J3_OK <unit>.path ActiveState=active UnitFileState=enabled Triggers=<unit>.service InvocationID=<id> ActiveEnterTimestampMonotonic=<n>

The last two fields are read right after that unit's enable, and the file contains nothing else. K2 takes the receipt's
absolute path and sha256 as arguments, re-reads both values live for each unit, and refuses unless all three lines equal
the live readings (fixture `k2-receipt`).
