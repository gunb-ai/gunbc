finding, and then executing the frame found two more:

- **N1 (BLOCKING): no cap in v5 could kill anything, and every `group-kill=1` receipt was false.** The launch left
  job control off, so the child was never a process-group leader; the group kill reached nothing; `wait` blocked

  reads each child's real process group from `/proc`, escalates group-TERM → group-KILL → direct-pid KILL, and emits a
  kill receipt ONLY when a post-kill liveness scan of the whole group finds nobody alive; otherwise the run is
  `KILL_FAILED` naming the surviving pids, exit 125, named separately from a timeout.

  documented cost-accounting refusal and no-observation statuses at the pin -- v5 printed `OUTCOME: PASS rc=0`. v6
  requires the recorded status to be 0 for PASS, and a FAIL line is decided BEFORE the status rule, because a real
  executor exits non-zero precisely when something refused (v17 exited 1 carrying 13 FAILs). My own hermetic control
  caught that ordering: as first written it turned a merit FAIL into NO_OBSERVATION, which would have buried the
  exact reds this packet exists to measure.

  header (the superseded 17-function rtp roster is kept, labelled, with the blob-pin move `514c1d32…` → `f2009028…`
