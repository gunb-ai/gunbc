# Remove `check-disallowed-methods.sh` guardrail script

**Status**: Completed
**Date**: 2026-02-14

## Context

`tools/check-disallowed-methods.sh` scans the repo for `#[allow(clippy::disallowed_methods)]`
attributes and checks them against an allowlist (`tools/disallowed-methods-allowlist.txt`).

The script had a longstanding false-positive bug (regex matched mentions in doc comments
and string literals, not just actual attributes). This was patched by tightening the
regex to `^\s*#!?\[allow\(`, but the script's value is questionable:

- The allowlist is auto-generated by `gunbc-pragma`, so it's always in sync.
- Clippy already enforces `disallowed_methods` — the script is a redundant second check.
- Grep-based source scanning is fragile (false positives from comments/strings).

## Action

1. Remove `tools/check-disallowed-methods.sh` - done.
2. Remove `tools/disallowed-methods-allowlist.txt` - no tracked file existed (it is generated/ignored); no committed allowlist artifact remains.
3. Remove the guardrails step that invokes the script (in CI graph / Makefile) - done (CI guardrail now runs resource purity checks directly).
4. Verify `clippy::disallowed_methods` enforcement is sufficient on its own - done via workflow acceptance and guardrail command checks.

## Outcome

- Deleted: `tools/check-disallowed-methods.sh`
- Updated guardrail command: `gunbc-dag/src/ci/ops.rs` now runs only `cargo test -p gunbc-dag --test resource_purity_checks --quiet`
- Updated workflow acceptance assertion to match the new guardrail behavior.
