# Six immediate lifecycle consumers: one replacement cut

Read-only source audit, 2026-10-23. This roster is **six modules, not six functions or six independent stores**. Compute provider/discharge share one namespace family; session placement/activation share another. Credential acquisition and worktree claims have their own payloads and namespaces. All six move together at `gunbc.compute.attempt_lifecycle`; none keeps a direct-file lifecycle fallback.

## Shared process and deployment selectors

- `roadmap_belt_tick_cli::belt_run_once_cli` requires nonempty `GUNBC_BELT_SPAWN_WORKDIR`, then `belt_run_once_cli_in` uses `dashboard_instance_for_repo_root` and calls `belt_run_once_in`. Missing/unknown roots refuse instead of falling back to production. The main belt is event-driven now; do not describe all lifecycle recovery as a main-belt timer. Credential recovery separately retains a backstop timer.
- In-process dispatch is `roadmap_serve` -> `roadmap_belt_actuate::belt_dispatch_node_for_instance_over`; the manual CLI is `belt_dispatch_node_cli` -> `belt_dispatch_instance_selected/named`, requiring `GUNBC_BELT_INSTANCE_ID` from its admitted roster. Its current admitted list is srv1-live/srv2-deploy; that does not replace the broader instance roster used by deployment-scoped paths. Non-executable JSON projections are not extra process roots.
- `roadmap_dashboard_instance::dashboard_instance_dispatch_attempt_state_directory/root` match `DispatchStateScope`: instance-owned derives from `instance_root` and `attempt_state_child`; host-shared carries its declared attempt-state root. `srv1_live_dashboard_instance` is host-shared. The new logical namespace must retain this ownership/sharing fact, separately from its selected backend locator.
- Provisioning roots: `roadmap.dashboard_instance_directories::dashboard_instance_directory_demands` -> `roadmap_dashboard_instance_apply::dashboard_apply_owned_directories` with dashboard observation, and `live_deploy.spec::DeploymentSpec.directories` -> `live_deploy.emit::owned_directory_apply_steps` with `live_deploy.member_observe` directory observation. Keep both consumers in the cut. Compute subdirectory creation and session slot creation are additional imperative setup sites to eliminate or fold into the selected readiness producer.

## Hidden path coupling and companion state that the cut must disposition

1. `credential_recover_slot` repeatedly derives `instance_root` with `path_parent_directory(root)` for runtime observation and cleanup. A fabric bucket/address cannot replace that string while preserving meaning. Carry the actual logical instance context through acquisition and recovery, and keep credential custody local to its declared process context. `credential_slot_record`, `credential_admit_reader_or_discard`, `credential_terminate`, `credential_recover_root` and `credential_recover_slot` also directly read/enumerate file CAS and must move with their lifecycle writers.
2. `SessionPlacementStores` includes `slots_root`, `records_dir`, capacity `store` and `partition`. `session_placement_record_write`, `session_placement_release_write`, `session_settle_note`, `session_placement_file` and `session_placement_observe_at` operate on grant/release/note companions under `records_dir`. Retain or replace each under its existing contract; switching only the CAS calls leaves a split recovery authority. The design must name what remains physically local, why it is not a second lifecycle truth, and how the whole observation remains coherent.
3. Compute cleanup joins lifecycle state to leases whose first line identifies the owning seat directory (`compute_lease_holder_line`), worker-exit spool owners, and capacity event history. Any new logical store binding must replace that physical locator comparison with the same ownership fact, not make every lease appear foreign or strip the fence. `compute_recover_roots` currently searches flat plus dispatch subroots and refuses multiple holders, including an unreadable potentially-held slot; keep that behavior.
4. Worktree claim reads and enumeration bypass `attempt_slot_read` because the payload is domain-specific. An `attempt_lifecycle` signature change alone will not break those raw reads. Their replacement is part of the same cut.

## Shared transition, retention and fencing contract

`attempt_open_payload` forces `AttemptReserved`, validates the declared launch window (nonnegative, not above `compute_pre_launch_ceiling_seconds`), and commits with `ExpectSlotAbsent`. `attempt_advance_payload` reads/decodes, checks embedded reference and expected generation, allows Reserved -> Launching, refuses reopening to Reserved, and routes terminal transitions through the same CAS. `attempt_commit_bytes` admits digest/key and uses unwindowed `file_compare_and_set(...DefaultAccessCreateOnly...)`. Lost precondition is `AttemptLostRace`; unreadable/refused storage is `AttemptTransitionRefused`. The losing launch must never reach spawn.

The existing `file_compare_and_set` projects `KeepAllGenerations`. The six consumers ordinarily recover from enumerated current records; that does not prove they need an arbitrary history traversal API. But the retained generation line and stable reference nonreuse are current storage facts, and `compute_recover_exit` explicitly calls the terminal generation durable history. The cut must name surviving audit/retention/nonreuse obligations and preserve their data; it cannot select windowed/head-only storage merely because it also supports CAS. Fabric CAS currently has link-free per-key generation objects and heads; it supplies neither implicit namespace closure nor retained-history traversal by itself.

`recovery_trigger` respects the declared prelaunch deadline for Reserved, requires observed ended lifecycle for Launching, and exposes `RecoveryTerminalRecordMayRelease` for crash recovery. Generic lifecycle termination alone is not sufficient evidence that a process ended. Compute, credentials, activation and worktree cleanup each have additional evidence obligations; preserve them at their own authority.

For the one cut: fence/quiesce all writers and recoverers for these namespaces, enumerate and independently reconcile extant records and required retained history, preserve scopes and generation/reference identities, then switch both readers and writers to one selected authority. A restart must recover pre-cut open, launching and terminal-but-unreleased records. Do not use a new empty namespace or reset ordinals. New backend writes make rollback to an old snapshot unsafe; reverse transition needs its own reconciliation. This design document does not authorize touching live state.

## Evidence and search limits

Search used `rg` for every `import gunbc.compute.attempt_lifecycle`, then direct calls to its ten I/O functions, followed by each caller's enclosing function, direct production callers, setup and instance selectors. Read the domain implementations and shared transition functions; traced executable CLI/deployment and in-process serve roots above. Import-only/type-only users (e.g. `compute.test_run` and `roadmap_belt_actuate` import lifecycle vocabulary) are distinguished from the six immediate I/O modules. Strings, comments and citation declarations are not counted as executable callers. This is a source roster, not evidence of every externally supplied/live deployment or a mechanically complete transitive graph.
